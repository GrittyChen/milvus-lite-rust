# 0.4.0rc1 发行范围与说明

本文固定本版本的范围、限制与安装说明，作为 GitHub Release 正文的唯一内容来源，不记录随发布推进变化的状态。冻结提交与执行结果由 Release 附件中的候选结果给出，七个附件的哈希由 Release 正文的候选证据一节与链接的候选验收记录给出；是否已发布及公开下载结果以该正文为准。

这是以 Rust 实现的非官方 milvus-lite，与 Milvus／Zilliz 无隶属关系。该版本为预发布试用，不建议用于生产；RC 阶段通过本项目 GitHub Release 分发，不上传 PyPI。以下安装入口须等对应 Release 正式发布后使用。

## 相对 0.3.0rc3 的变化

本版新增四组对外能力，参照固定为官方 milvus-lite v3.2.1／`43d1257774e629bc9f66873977ab7c320d5bf5a7`，与参照的逐项差异登记在 [0006 差异表](../decisions/0006-m2-scope.md#与-3x-的差异)：

- **集合管理与多数据库**（[0023](../decisions/0023-aliases-rename-truncate-databases.md)）：别名的创建、改指、删除、查询与列表，所有集合 RPC 解析别名；RenameCollection（同库内）；TruncateCollection（保留分区、索引定义、别名与 load 状态，auto_id 从 1 重新分配）；AlterCollection 的集合属性；CreateDatabase / DropDatabase / ListDatabases / DescribeDatabase / AlterDatabase，请求按 `db_name` 与 `dbname` 元数据路由，各库内的别名、改名、清空与属性互相独立。
- **分组检索**（[0024](../decisions/0024-group-by-search.md)）：Search 的 `group_by_field`、`group_size`、`strict_group_size`，候选窗口与按组展平后的 offset 与 3.x 一致。
- **TIMESTAMPTZ 与 `timezone`**（[0025](../decisions/0025-timestamptz-and-timezone.md)）：TIMESTAMPTZ 标量类型（内部 UTC 微秒，读出以 `Z` 结尾的 ISO 字符串）；过滤中的 `ISO '…'`、`INTERVAL '…'` 与时间戳加减区间；无偏移时间字符串按请求、集合、数据库 `timezone` 的优先级换算；Query 与 Search 的 `time_fields`。
- **HybridSearch 与 rerank**（[0026](../decisions/0026-rerank-and-hybrid-search.md)）：`hybrid_search` 的 RRF / Weighted；Search 与 HybridSearch 的 `function_score`（任意个 boost 加最多一个 rrf / weighted / decay）；rerank 链内的分组；HybridSearch 各路的过滤、分区、度量与时区。

新增运行依赖 jiff 0.2.38（纯 Rust，无构建脚本），内置 tzdata 2026e：时区换算不依赖运行平台的时区数据，时区名不区分大小写。其余依赖与 Rust 1.98.1 工具链不变。

`0.3.0rc2` 的 JSON 写入优化、`0.3.0rc1` 的显式分区、partition key 与请求前状态独立合并的非 key Upsert，以及更早版本的 nullable / 默认值、ARRAY、Query iterator、range search / Search iterator V1 均继续保留，见 [0015](../decisions/0015-nullable-defaults-and-array.md)、[0016](../decisions/0016-query-iteration-and-range-search.md)、[0017](../decisions/0017-partitions.md)、[0018](../decisions/0018-json-write-normalization.md)。

## 与 3.x 的主要已登记差异

完整清单与理由见 [0006 差异表](../decisions/0006-m2-scope.md#与-3x-的差异)，下面只摘要：

- **集合管理与多数据库**：跨数据库改名为 UNIMPLEMENTED；改名不覆盖任何已有路径（悬空别名与残留目录都拒绝）；范围外 schema 上的清空与改属性为 UNIMPLEMENTED；别名路径与 `schema.json` 的 I/O、解析失败向上报错，不像 3.x 那样当作不存在继续执行（create 可能因此由成功变为失败，见 0006）；数据库属性值只接受字符串；创建与打开集合不读数据库属性文件（只有需要数据库时区的操作才按需读取）；数据库在打开时枚举；`databases/` 与 `.database-staging/` 须在同一文件系统；只差大小写的数据库名按精确名字处理。
- **分组检索**：3.x 在主键名不是 `id`、或可空分组字段叫 `distance` / `id` 时的错误结果不复制，本实现按字段值正常分组。
- **TIMESTAMPTZ**：原始 gRPC 写入越界的整数微秒时整批拒绝（3.x 写入成功、之后读到该行的查询都失败）；`ARRAY<TIMESTAMPTZ>` 为 UNIMPLEMENTED；不涉及时间值的算术仍为 UNIMPLEMENTED；时区名的大小写与平台文件（`posixrules`、`localtime` 等）的处理与依赖系统 tzdata 的 3.x 不同。
- **HybridSearch 与 rerank**：以下返回 UNIMPLEMENTED：① Search 与 HybridSearch 顶层实际执行的 model rerank（外部 provider，测试不依赖付费服务）；② 候选真正用到的 boost `random_score`；③ Search 的公共 `function_chains`（HybridSearch 的 `function_chains` 与 3.x 一样报错）；④ boost 过滤里的算术与 `text_match`；⑦ rerank 算出的得分写进同名的 TIMESTAMPTZ / ARRAY / 向量字段。另有 `rank_params` 整数超出 int64 时按饱和值执行、子请求 `params` 不是严格 JSON 时拒绝、分组排序键含 NaN 时组内顺序不逐位复现。多向量字段与 BM25 / 稀疏向量不在本版范围。

## 相对 0.3.0rc3 新拒绝或改变的行为

- **共享 JSON 按键排序写出**：`schema.json`、`aliases.json`、`database_properties.json` 与 manifest 改为与 3.x 相同的键排序格式。只有改写这些文件时才规范化（flush 写 manifest；Alter、清空、改名写 `schema.json`；别名操作写 `aliases.json`），只打开不重写；用户可见的效果是重开后集合属性按键序返回，与 3.x 一致。
- **CreateIndex 参数中超出有限 float64 范围的数字**（raw gRPC，如 `{"x": 1e999}`）：`0.3.0rc3` 接受并写入 manifest，本版返回 UNIMPLEMENTED、不写入定义。`0.3.0rc3` 已写出的这类存量定义继续保留严格 JSON 的数字文本，不写 `Infinity`。
- **数据根下的 `databases` 不是目录或不可读时启动失败**：`0.3.0rc3` 不使用该路径，照常启动。
- **`schema.json` 的 `collection_name` 与目录名不同的集合可以打开**：`0.3.0rc3` 拒绝打开这类集合；本版只要该值是字符串就打开，集合名取目录名。这类目录来自外部写入或中断的改名，见 [0023](../decisions/0023-aliases-rename-truncate-databases.md)。
- **原先失败的请求现在执行**：上一节列出的别名、改名、清空、集合与数据库属性、数据库 RPC、TIMESTAMPTZ、分组检索、HybridSearch 与 `function_score` 原先返回 UNIMPLEMENTED；经 `db_name` 访问已有的非默认库原先报数据库不存在，现在可以使用。依赖这些请求必然失败的调用方需要调整。

## 兼容性与已知限制

- **数据格式**：数据文件沿用 schema.json、Arrow IPC WAL、Parquet 与 manifest format 2 编码，不增加私有数据格式；改名与清空各有一个短暂存在的私有意图文件（文件名与格式见 [0002](../decisions/0002-data-dir-compat.md)），由本实现重开时收尾。已发布的 `0.3.0rc3` 读取本版写出的普通与 partition key 集合目录，partition key 集合再由本版重开核对旧版的追加，由候选验收在 Linux x86_64 上核验。
- **降级到 0.3.0rc3 及更早**：
  - 降级前须用本版正常打开并关闭一次数据目录，让未收尾的改名、清空意图处理完毕；意图未处理时降级的影响见 [0023](../decisions/0023-aliases-rename-truncate-databases.md)。
  - 非默认数据库：旧版的数据库 RPC 返回 UNIMPLEMENTED，经 `db_name` 访问已有的非默认库报数据库不存在（code 1），库内集合不可访问，数据保留。
  - 含 TIMESTAMPTZ 字段的集合、带 `timezone` 属性的集合：旧版明确拒绝（UNIMPLEMENTED），数据与属性保留；只带其他属性的集合不受影响。默认库的数据库属性不影响旧版访问集合，但旧版的 DescribeDatabase 返回 UNIMPLEMENTED。
  - 别名：旧版的别名 RPC 返回 UNIMPLEMENTED，按别名访问报集合不存在，`aliases.json` 保留；旧版 create 集合时剔除指向不存在目标的别名、drop 集合时删除指向被删集合的别名，也拒绝与现有别名同名的集合名。降级期间没有删除目标集合时，升级回来后别名照常可用。
  - 降级到 `0.2.0rc1` 及更早的拒绝边界（非默认分区、partition key、nullable / ARRAY）继续保留，见 [0017](../decisions/0017-partitions.md)、[0015](../decisions/0015-nullable-defaults-and-array.md)。
- **停服路径的一次段错误，根因未查明。** 持续集成试点中，Linux x86_64 的一次差分运行在停服路径上出现过一次进程段错误；此后 valgrind 检查与停服时序定向压力（合计 41568 轮）都没有再现，此后的运行中也没有再现（检索范围见候选方案）。本版的产品代码相对上一次风险接受有变化：停服顺序本身与相关原生依赖不变，变化的是最终 flush 与打开路径中的安全 Rust 代码和一个纯 Rust 依赖，没有新的定向压力证据。本版据此**再次**做显式发布级风险接受，不是修复，适用范围与依据见[候选方案](0.4.0rc1-candidate-plan.md)；候选或后续运行再次出现即撤回这一接受，转回根因调查（[调查记录](../testing/shutdown-segfault-investigation.md)）。
- 分区名称、实际目录身份及 snapshot pins 按 0017 的安全合同检查；partition key 的 B1 / B2 / B3 差异继续披露：生成 ID 取分桶后行 seq，可能为 `[1,3,2]`；所有桶的确定性校验完成后才追加 WAL；自动 ID 将覆盖请求前可读旧行时整批拒绝。
- 过滤继续按参照的整条表达式路线执行，缺失值、null、短路及类型错误依路线而异。算术（时间戳加减区间除外）与几何谓词仍为范围外。
- 距离沿用 [0004](../decisions/0004-m1-scope.md) 的浮点误差预算；范围阈值落在误差带内时，两端可能有成员或数量差异。
- Search iterator V1 依赖 SDK 的有限探测算法，部分批量和距离分布下会提前结束；服务端忽略 V2 探测参数，SDK 据此自动回退 V1，与参照一致。
- 两条 SDK 的端点 schema 缓存限制仍存在：同一进程中显式释放后复用端口，或 CLI 在固定端口更换数据目录重启，可能使 SDK 沿用旧 schema；真实 3.x 上同样存在。
- 向量仍仅以 FLAT 执行，已接受的 ANN 定义不意味着实际 ANN；INVERTED 定义的执行仍为扫描。存量定义、DropIndex 及持久化未确认时的封锁与恢复沿用 [0014](../decisions/0014-index-definitions-and-filter-expressions.md) 和 [README](../../README.md)。
- LoadPartitions / ReleasePartitions、snapshot RPC、稀疏向量、BM25 与全文检索、公共 function chain、model rerank、多向量字段、nullable 向量、真实 ANN、GEOMETRY、AddCollectionField／AlterCollectionSchema 不在本版范围。
- JSON 写入优化的收益限于 [0018 已审同机工况](../testing/0018-json-write-acceptance.md)，不外推为任意 JSON、并发吞吐或全部写入路径的保证；进程峰值资源差距尚未解决，继续单独跟进。

## 平台、解释器与证据边界

四个平台均为标准层，在发行工作流中执行相同的适用门槛（[0021](../decisions/0021-release-build-in-ci.md) 第 9、14–16 条）：Linux x86_64 与 arm64 在 GitHub 托管机器上固定的 manylinux_2_28 容器（glibc 2.28）中执行，macOS arm64 在 `macos-15`、macOS x86_64 在 `macos-15-intel` 上原生执行。各平台覆盖正式 wheel 的归档与二进制检查、Rust 默认与故障注入构建的单测、CPython 3.10 与 3.15 上两条 SDK（pymilvus 2.6.17／3.0.2）的端到端全套、3.11–3.14 联合冒烟、正式 wheel 上与官方 3.x 的差分及 Arrow 15/25 数据互通，以及故障注入测试包的恢复专项；Linux 另验 LOCK、strace 与容器 PID 1，Linux x86_64 另验已发布 `0.3.0rc3` 读取本版写出的目录。sdist 另验构建根、PEP 517 安装、Rust 1.89 MSRV 与各项构建期拒绝。

Windows、free-threaded 和非 CPython 在构建时明确拒绝。musl、其它架构及较低 glibc 的自行构建仅为实验性尝试。Linux 容器的宿主内核是托管机器的较新版本，托管机器没有 macOS 11；二进制的最低系统字段由检查核对，不等于真机最低系统、真实断电或任意文件系统持久化已经验证。

FI wheel 仅供隔离验收，不随发行分发。旧线是否继续发修复版按实际需求另定；本候选不承诺持续维护多个版本线，也不自动将任何 RC 转为正式版。

## 安装（对应 Release 发布后）

本包与官方 milvus-lite 共用 `milvus_lite` 模块，不可同时安装；不用 `pymilvus[milvus-lite]`。

```bash
python -m pip uninstall milvus-lite
python -m pip install pymilvus
python -m pip install --no-index --only-binary :all: --find-links https://github.com/GrittyChen/milvus-lite-rust/releases/expanded_assets/v0.4.0rc1 milvus-lite-rust==0.4.0rc1
```

也可从 [v0.4.0rc1 Release](https://github.com/GrittyChen/milvus-lite-rust/releases/tag/v0.4.0rc1) 下载本平台 wheel 与 SHA256SUMS，核对后安装：

```bash
shasum -a 256 -c --ignore-missing SHA256SUMS && python -m pip install --no-index ./milvus_lite_rust-0.4.0rc1-*.whl
```

Linux 可用 sha256sum 执行同样的校验。需要核对来源时，在下载目录用已登录的 GitHub CLI 执行本平台对应的一行，成功即说明该文件由本仓库的发行工作流签发：

```bash
gh attestation verify milvus_lite_rust-0.4.0rc1-cp310-abi3-manylinux_2_28_x86_64.whl --repo GrittyChen/milvus-lite-rust --signer-workflow GrittyChen/milvus-lite-rust/.github/workflows/release.yml
gh attestation verify milvus_lite_rust-0.4.0rc1-cp310-abi3-manylinux_2_28_aarch64.whl --repo GrittyChen/milvus-lite-rust --signer-workflow GrittyChen/milvus-lite-rust/.github/workflows/release.yml
gh attestation verify milvus_lite_rust-0.4.0rc1-cp310-abi3-macosx_11_0_arm64.whl --repo GrittyChen/milvus-lite-rust --signer-workflow GrittyChen/milvus-lite-rust/.github/workflows/release.yml
gh attestation verify milvus_lite_rust-0.4.0rc1-cp310-abi3-macosx_11_0_x86_64.whl --repo GrittyChen/milvus-lite-rust --signer-workflow GrittyChen/milvus-lite-rust/.github/workflows/release.yml
```

sdist 的 Python 下限及 Rust 1.89 MSRV 沿用 [源码回退门槛](../../tests/packaging/README.md#源码与拒绝门槛)，不引导从 PyPI 按项目名解析本包。
