## 已确认版本与范围

采用 Python `0.3.0rc2` / Cargo `0.3.0-rc.2`，继承 `0.3.0rc1` 的功能和已登记差异，仅增加已审的 0018 JSON WAL 编码复用。它是现有写入路径的优化，无新 RPC、数据类型、存储格式或依赖，继续在 0.3 RC 内验证，不因本次优化转为正式版或新次版本。

本地实施提交同时包含调查、诊断工具输出保护、实施测试及验收记录。这些工具属于开发证据，不作为运行时能力或公开发行附件。峰值资源差距继续单独调查，不纳入本候选的优化承诺；alias / rename、BM25、真实 ANN、nullable 向量等能力保持原范围。

发行说明应写明：复用首轮已校验、规范化的 JSON 文本，原校验、错误优先级、全桶预构造、I/O 前缀恢复及持久化保证保持；不改变请求结果或降级边界。相对 `0.3.0rc1` 的无格式变化须由最终产物互通验证支持，不能推导为可降级到更早的不支持分区 / schema 的版本。

31.6% / 22.8% 是 0018 已审同机 mixed raw / SDK Insert 工况的降幅，基线、输入和产物身份见原验收记录，不是下一候选已经测出的结果。若对新候选单独声明百分比，须使用最终产物重测；不把历史数字回填为新候选成绩，不宣称峰值资源目标已经解决。

## 执行检查点

1. 确认本方案后再修改版本、锁文件、README 安装入口、打包检查器及其当前版本断言，同步打包工具 README 的默认版本，新增固定的 `0.3.0rc2` 发行说明。保留已发布版本的说明及附件，发行正文以新版本文档为唯一内容来源。
2. 对准备变更运行相关打包 / 平台工具自检、fmt、默认及完整三层 FI 编译检查，交审阅。准备变更通过且获准本地提交后，再从该提交冻结源码；不在冻结身份未确定时启动长时间矩阵。
3. 为冻结提交重新生成完整源树与产品 / 构建输入清单、归档哈希及工具身份。0018 的 127 项输入只标识开发实施；版本切换后的候选须有新指纹。逐文件证明除获审准备文件外，产品和测试与实施提交一致。
4. 从冻结归档重建四个正式 wheel、sdist 及三标准层的隔离 FI wheel，执行 0013 的完整候选门槛。本次产品原生代码相对 `0.3.0rc1` 已改变，不适用仅文档变更、执行载荷相同的旧矩阵沿用例外。
5. 交付候选验收记录、固定发行正文、附件校验和及证据包，交独立复审。候选通过后再分别授权推送、创建指向构建冻结提交的 tag 和 Release 发布；公开下载、安装及不可变状态在发布后验证。

## 候选验收重点与证据边界

完整门槛以 0013 为准，不能把本表当作缩减矩阵。继续使用 Linux 两种架构、macOS arm64 的标准层及 Intel Mac 的既定构建 / 冒烟层级，不追加原生 Intel 全套、最低系统真机或真实断电门槛。

| 范围 | 本候选应核验的内容 |
| --- | --- |
| 身份与打包 | 冻结归档、工具、正式 / FI 产物与安装后的 native 对应；README 与 wheel / sdist 长描述一致；四正式 wheel、sdist 和 SHA256SUMS |
| 平台与编译 | 默认及完整 py → grpc → core FI 编译面、MSRV、二进制 / glibc / 部署字段；标准层解释器端点及两 SDK 全套、Linux 差分 / 互通 / LOCK / strace / PID 1、Intel Mac 既定冒烟 |
| JSON 写入 | 普通及 key 的 Insert / Upsert，nullable / 默认值、完整 / 紧凑掩码、精确 WAL 文本、错误优先级与失败无写入；通用入口继续校验，可信入口不能绕过首轮规范化 |
| 存储与生命周期 | WAL 重放、Flush、实际 compaction、再次重开；Arrow 15 / 25 双向互通；已发布 `0.3.0rc1` 读取新产物生成的兼容目录；既有旧版拒绝及联合生命周期门槛 |
