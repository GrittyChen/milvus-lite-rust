# 0.6.0rc1 发行范围与说明

本文固定本版本的范围、限制与安装说明，作为 GitHub Release 正文的唯一内容来源，不记录随发布推进变化的状态。冻结提交与执行结果由 Release 附件中的候选结果给出，七个附件的哈希由 Release 正文的候选证据一节与链接的候选验收记录给出；是否已发布及公开下载结果以该正文为准。

这是以 Rust 实现的非官方 milvus-lite，与 Milvus／Zilliz 无隶属关系。该版本为预发布试用，不建议用于生产；RC 阶段通过本项目 GitHub Release 分发，不上传 PyPI。以下安装入口须等对应 Release 正式发布后使用。

## 相对 0.5.0rc1 的变化

参照仍为官方 milvus-lite `1320d26ec3d88b23b525e774df6e3c8e7c208f81`，与参照的逐项差异登记在 [0006 差异表](../decisions/0006-m2-scope.md#与-3x-的差异)。新增三组对外能力：

- **过滤中的算术**（[0032](../decisions/0032-arithmetic-filters.md)）：`+`、`-`、`*`、`/` 与一元负号，可用于 Query、count、iterator、Search、稀疏检索、HybridSearch、Delete 与 boost 过滤。按 3.x 的三条求值路线复刻：只引用 schema 字段时按 pyarrow 的类型提升、回绕与带检查的转换计算；含 JSON 路径时按 Python 计算（整数精确、整数相除正确舍入、字符串与列表的拼接和重复）；含动态字段键时先按列计算，类型不合适时整条表达式改按 Python 计算。
- **GEOMETRY 字段与几何谓词**（[0034](../decisions/0034-geometry.md)）：标量类型 GEOMETRY（WKT 文本，`POINT` 与单环、不自交的 `POLYGON`，原文保存），支持 nullable 与默认值；`ST_CONTAINS`、`ST_WITHIN`、`ST_INTERSECTS`、`ST_DWITHIN`、`ST_ISVALID` 及其 `geometry_*` 同义写法，可用于各类读取、Delete 与 boost 过滤。谓词复刻 3.x 自己的平面近似算法（容差 1e-9），不是 OGC 语义。
- **公共 function chain**（[0035](../decisions/0035-function-chains.md)）：Search 的 `function_chains`（pymilvus 3.0 的 `client.search(function_chains=FunctionChain(...))`）：L2 rerank 阶段的一条链，算子 `map` / `sort` / `limit`，表达式 `num_combine`、`decay` 与 `round_decimal`；链在普通检索返回的命中上执行，不放大候选窗口。

另外，hybrid 路线中动态字段的类型推断改为按 pyarrow 的实际规则复刻（[0033](../decisions/0033-hybrid-dynamic-inference.md)），注销了 0032 登记的推断差异。

没有新增依赖包：过滤 Python 路线的精确整数改为直接使用 num-bigint 0.5.1，它此前已经随 arrow-buffer 出现在依赖图中，版本与来源不变；Rust 1.98.1 工具链不变。`0.5.0rc1` 及更早版本的能力（`text_match` 与分析器属性、稀疏向量、BM25、多向量字段、集合管理与多数据库、分组检索、TIMESTAMPTZ 与 `timezone`、HybridSearch 与 rerank、显式分区与 partition key、nullable / 默认值、ARRAY、Query iterator、range search / Search iterator V1、JSON 写入优化）继续保留，见 [0015](../decisions/0015-nullable-defaults-and-array.md)–[0018](../decisions/0018-json-write-normalization.md)、[0023](../decisions/0023-aliases-rename-truncate-databases.md)–[0031](../decisions/0031-bm25.md)。

## 与 3.x 的主要已登记差异

完整清单与理由见 [0006 差异表](../decisions/0006-m2-scope.md#与-3x-的差异)，下面只摘要本版新增的部分：

- **算术的资源上限**：字符串、列表与大整数的中间结果有上限（单个值与每行累计 64 MiB，整数 2^20 位），超出时报 code 1；3.x 没有上限，内存不足时报 MemoryError。上限只约束内存，不约束 CPU 与时间。见 [0032「与 3.x 的差异」](../decisions/0032-arithmetic-filters.md#与-3x-的差异)。
- **只看活行**：hybrid 路线推断动态字段类型时只看未删除的行，3.x 也看已删除的旧行，个别数据上一个报错、一个改按 Python 计算。
- **Arrow 版本**：动态字段的值是多键对象时，对象字段按 3.x 在 pyarrow 25 下的首次出现顺序处理；pyarrow 15 下的 3.x 按键名排序，个别情形一个报错、一个改按 Python 计算（[0033](../decisions/0033-hybrid-dynamic-inference.md)）。
- **GEOMETRY**：`ARRAY<GEOMETRY>` 建表与打开都返回 UNIMPLEMENTED（3.x 可以建表，但写入的元素读不出），已有这种集合的 3.x 数据目录，该集合无法打开、可以 drop；`ST_DWITHIN` 的距离按 CPython 3.12 的 `math.hypot` 计算，3.x 运行在其他 CPython 版本上时，恰好落在阈值上的行可能不同。
- **公共 function chain**：`output_fields` 含 `*` 或整个动态字段时返回真实的字段值（3.x 返回类型默认值与残缺的动态字段）；通过全部校验的 `rerank_model` 返回 UNIMPLEMENTED（3.x 调用外部 provider）；分组字段恰好叫 `$score` / `$id` 时，分数与主键不被分组值覆盖（3.x 会覆盖）。见 [0035「与 3.x 的差异」](../decisions/0035-function-chains.md#与-3x-的差异)。

## 相对 0.5.0rc1 新拒绝或改变的行为

- **动态字段的类型推断**（hybrid 路线，含顶层动态字段过滤与引用动态字段键的布尔树）：同一个键在各行取值类型混杂时，此前一律改按 Python 计算，现在与 3.x 一样先按 pyarrow 的规则推断与转换。此前这类数据源整体回退 Python，结果或错误取决于表达式（如字符串运算可能报 TypeError）。现在推断出整数类型而值超出 int64 时（如先出现 `2**63`、后出现字符串），与 3.x 一样报 `Python int too large to convert to C long`；部分不报错的请求也可能得到不同的结果：按列计算时整数按 int64 回绕、除以零得到 inf / nan，`[1.5, True]` 这样的取值按 double 计算（`True` 为 1.0）。规则与对照表见 [0033「与现状的对比」](../decisions/0033-hybrid-dynamic-inference.md#与现状的对比)。
- **整数与浮点列的比较**：Arrow 路线上整数列与浮点列比较时，按整数一侧自己的有效行检查能否精确转换为浮点（与 3.x 相同）；此前只检查两侧都有效的行，因此两侧空值错位、整数一侧含超过 2^53 的值时，现在与 3.x 一样报错，此前返回结果（[0032「已并入第 1 步修正的既有问题」](../decisions/0032-arithmetic-filters.md#已并入第-1-步修正的既有问题)）。
- **ARRAY 字段上的 LIKE**：Arrow 路线上的报错文案改为与 3.x 相同的 `Function 'match_like' has no kernel matching input types (...)`，错误码不变（code 1）。
- **超出 f64 范围的 JSON 数字的真值**：`1e999` 这类数字按 Python 的 `inf` 判断为真，与 3.x 相同，此前判断为假。影响 `search_params` 的 `strict_group_size`、`function_score` 中 provider 是否存在的判断，以及建表属性的布尔取值。
- **原先失败的请求现在执行**：过滤中的算术（包括 boost 过滤里的算术）、GEOMETRY 字段与几何谓词、Search 的 `function_chains` 原先返回 UNIMPLEMENTED，带 GEOMETRY 字段的 3.x 集合原先打不开。依赖这些请求必然失败的调用方需要调整。

## 兼容性与已知限制

- **数据格式**：数据文件沿用 schema.json、Arrow IPC WAL、Parquet 与 manifest format 2 编码，不增加私有数据格式；GEOMETRY 与 3.x 相同，按字符串列存写入的原文，`schema.json` 的 `dtype` 为 `geometry`。已发布的 `0.5.0rc1` 读取本版写出的普通与 partition key 集合目录，partition key 集合再由本版重开核对旧版的追加，由候选验收在 Linux x86_64 上核验。
- **降级到 0.5.0rc1 及更早**（macOS arm64 实测）：
  - 普通与 partition key 集合（只在 WAL、已 flush、flush 后删除并追加三种状态）可以正常读写，再升级回来数据完整。
  - 带 GEOMETRY 字段的集合在旧版 load 时明确返回 UNIMPLEMENTED（`field "g" has dtype "geometry"`），可以 drop，数据保留，升级回来后照常可用。算术、几何谓词与 function chain 的请求在旧版返回 UNIMPLEMENTED，不涉及数据。
  - 降级到 `0.4.0rc1` 及更早的拒绝边界（多向量字段、稀疏向量、BM25 function、分析器属性）继续适用，见 [0.5.0rc1 发行说明](0.5.0rc1.md#兼容性与已知限制)；更早版本的边界见该文链接的各版本说明。
- **停服路径的一次段错误：根因未查明，显式风险接受，不是修复。** 持续集成试点中，Linux x86_64 的一次差分运行在停服路径上出现过一次进程段错误；此后 valgrind 检查与停服时序定向压力（合计 41568 轮）都没有再现，此后的运行中也没有再现（检索范围见候选方案）。本版相对 `0.5.0rc1` 停服路径逐字未变，服务生命周期、原生交界与停服相关依赖也没有改动，残余风险集合扩大：停服时可能在途的请求处理中新增了安全 Rust 的计算代码（算术、几何、function chain），这些新代码与 `0.5.0rc1` 已接受的各项一样，没有托管机器上的定向压力证据。本版据此在负责人确认后**继承** `0.5.0rc1` 的显式发布级风险接受，依据与适用范围见[候选方案](0.6.0rc1-candidate-plan.md#停服段错误继承-050rc1-的发布级风险接受)；候选或后续运行再次出现即撤回这一接受，转回根因调查（[调查记录](../testing/shutdown-segfault-investigation.md)）。
- 过滤继续按参照的整条表达式路线执行，缺失值、null、短路及类型错误依路线而异；`%` 与 `**` 与 3.x 一样是解析错误。
- 距离沿用 [0004](../decisions/0004-m1-scope.md) 的浮点误差预算；范围阈值落在误差带内时，两端可能有成员或数量差异。BM25 与稀疏 IP 的分数按 3.x 逐位对齐，不使用这一误差预算；function chain 里经过 `decay` 的分数随平台数学库可能差几个 ULP，3.x 换平台同样如此。
- Search iterator V1 依赖 SDK 的有限探测算法，部分批量和距离分布下会提前结束；服务端忽略 V2 探测参数，SDK 据此自动回退 V1，与参照一致。
- 两条 SDK 的端点 schema 缓存限制仍存在：同一进程中显式释放后复用端口，或 CLI 在固定端口更换数据目录重启，可能使 SDK 沿用旧 schema；真实 3.x 上同样存在。
- 向量仍仅以 FLAT 执行，已接受的 ANN 定义不意味着实际 ANN；INVERTED 定义的执行仍为扫描。存量定义、DropIndex 及持久化未确认时的封锁与恢复沿用 [0014](../decisions/0014-index-definitions-and-filter-expressions.md) 和 [README](../../README.md)。
- LoadPartitions / ReleasePartitions、snapshot RPC、jieba、TEXT_EMBEDDING、model rerank、boost 的 `random_score`、`ARRAY<TIMESTAMPTZ>` 与 `ARRAY<GEOMETRY>`、nullable 向量、真实 ANN、AddCollectionField／AlterCollectionSchema 不在本版范围。
- 稀疏向量检索在 nq 较大时仍慢于 2.5.1（[0030 验收](../decisions/0030-sparse-vectors.md#验收)中 nq=32 约慢 27%），单条查询与过滤检索追平或更快。
- JSON 写入优化的收益限于 [0018 已审同机工况](../testing/0018-json-write-acceptance.md)，不外推为任意 JSON、并发吞吐或全部写入路径的保证；进程峰值资源差距尚未解决，继续单独跟进。

## 平台、解释器与证据边界

四个平台均为标准层，在发行工作流中执行相同的适用门槛（[0021](../decisions/0021-release-build-in-ci.md) 第 9、14–16 条）：Linux x86_64 与 arm64 在 GitHub 托管机器上固定的 manylinux_2_28 容器（glibc 2.28）中执行，macOS arm64 在 `macos-15`、macOS x86_64 在 `macos-15-intel` 上原生执行。各平台覆盖正式 wheel 的归档与二进制检查、Rust 默认与故障注入构建的单测、CPython 3.10 与 3.15 上两条 SDK（pymilvus 2.6.17／3.0.2）的端到端全套、3.11–3.14 联合冒烟、正式 wheel 上与官方 3.x（`1320d26`，NumPy 2）的差分及 Arrow 15/25 数据互通，以及故障注入测试包的恢复专项；Linux 另验 LOCK、strace 与容器 PID 1，Linux x86_64 另验已发布 `0.5.0rc1` 读取本版写出的目录。sdist 另验构建根、PEP 517 安装、Rust 1.89 MSRV 与各项构建期拒绝。

Windows、free-threaded 和非 CPython 在构建时明确拒绝。musl、其它架构及较低 glibc 的自行构建仅为实验性尝试。Linux 容器的宿主内核是托管机器的较新版本，托管机器没有 macOS 11；二进制的最低系统字段由检查核对，不等于真机最低系统、真实断电或任意文件系统持久化已经验证。

FI wheel 仅供隔离验收，不随发行分发。旧线是否继续发修复版按实际需求另定；本候选不承诺持续维护多个版本线，也不自动将任何 RC 转为正式版。

## 安装（对应 Release 发布后）

本包与官方 milvus-lite 共用 `milvus_lite` 模块，不可同时安装；不用 `pymilvus[milvus-lite]`。

```bash
python -m pip uninstall milvus-lite
python -m pip install pymilvus
python -m pip install --no-index --only-binary :all: --find-links https://github.com/GrittyChen/milvus-lite-rust/releases/expanded_assets/v0.6.0rc1 milvus-lite-rust==0.6.0rc1
```

也可从 [v0.6.0rc1 Release](https://github.com/GrittyChen/milvus-lite-rust/releases/tag/v0.6.0rc1) 下载本平台 wheel 与 SHA256SUMS，核对后安装：

```bash
shasum -a 256 -c --ignore-missing SHA256SUMS && python -m pip install --no-index ./milvus_lite_rust-0.6.0rc1-*.whl
```

Linux 可用 sha256sum 执行同样的校验。需要核对来源时，在下载目录用已登录的 GitHub CLI 执行本平台对应的一行，成功即说明该文件由本仓库的发行工作流签发：

```bash
gh attestation verify milvus_lite_rust-0.6.0rc1-cp310-abi3-manylinux_2_28_x86_64.whl --repo GrittyChen/milvus-lite-rust --signer-workflow GrittyChen/milvus-lite-rust/.github/workflows/release.yml
gh attestation verify milvus_lite_rust-0.6.0rc1-cp310-abi3-manylinux_2_28_aarch64.whl --repo GrittyChen/milvus-lite-rust --signer-workflow GrittyChen/milvus-lite-rust/.github/workflows/release.yml
gh attestation verify milvus_lite_rust-0.6.0rc1-cp310-abi3-macosx_11_0_arm64.whl --repo GrittyChen/milvus-lite-rust --signer-workflow GrittyChen/milvus-lite-rust/.github/workflows/release.yml
gh attestation verify milvus_lite_rust-0.6.0rc1-cp310-abi3-macosx_11_0_x86_64.whl --repo GrittyChen/milvus-lite-rust --signer-workflow GrittyChen/milvus-lite-rust/.github/workflows/release.yml
```

sdist 的 Python 下限及 Rust 1.89 MSRV 沿用 [源码回退门槛](../../tests/packaging/README.md#源码与拒绝门槛)，不引导从 PyPI 按项目名解析本包。
