## 停服段错误：继承 0.5.0rc1 的发布级风险接受

`0.5.0rc1` 的接受以它的 `crates/` 树 `73fb12ff…` 为适用范围，本版 `crates/` 与 `Cargo.lock` 有变化，不自动适用。按调查记录「失效与继承」第二条：差异若不涉及停服、服务生命周期、原生交界或停服相关依赖，写明比较的提交与差异范围、经负责人明确确认后可以继承。负责人评审同意**继承**，依据是下面相对 `fd70faf` 的只读核对；方案中的同意不代替确认，继承须由负责人在候选验收记录中明确确认。

相对 `0.5.0rc1` 冻结提交 `fd70faf` 的核对结果：

1. **停服顺序与服务生命周期逐字未变**：`crates/core/src/db.rs`、`maintenance.rs`、`compute.rs`、`crates/grpc/src/server.rs` 与整个 `crates/py`（含 Python 包）没有任何改动。存储层只改了 `storage/arrow_data.rs`、`storage/memtable.rs`、`storage/schema_file.rs` 中 GEOMETRY 到字符串列与 `dtype` 名的映射（各 1–3 行），flush、WAL、恢复、compaction 与 manifest 的代码没有改动。
2. **在途请求的处理体有新增代码**（都是安全 Rust）：过滤的算术（`filter/python_num.rs` 等，大整数与字符串 / 列表结果先 `try_reserve` 再分配，单值与每行累计 64 MiB）、几何解析与谓词（`geometry.rs`）、function chain 的解码与执行（`crates/grpc/src/function_chain.rs`、`rerank/public.rs`）。`crates/grpc/src/service.rs` 只在 Search 处理体内、持读锁期间多一次链的准备，并把结果传给检索；检索计算仍只经 `Compute::for_each`。它们不由停服函数调用，但可能在在途请求中与停服并发执行。
3. **原生交界**：`crates/` 的差异里没有新增 `unsafe`、`extern "C"`、`libc::`、`transmute`，没有新建线程或新的 PyO3 交界。
4. **依赖**：见上节，只多一条已存在包的依赖边；Rust 1.98.1；CI 固定的 grpcio 1.84.0、protobuf 7.36.2、pymilvus 2.6.17 / 3.0.2 不变。
5. **新代码上没有再现**：自 `0.5.0rc1` 冻结分支的运行（`43032103700` / `43032103640`）起至 D 的最后一次运行（含两端），`CI` 19 次、`Compare` 15 次，发行工作流 2 次（`0.5.0rc1` 的演练与正式运行）。`CI` 有 1 次失败（`43801249752`，0035 第 3 步的工作分支）：两个 Linux 的 rust job 中 `rerank::public::tests::execution_matches_the_reference_fixture` 的一处 decay 断言差 1 ULP，单测断言失败、进程正常退出，原因与修正见 [0035 第 3 步验收](../decisions/0035-function-chains.md#第-3-步验收)；其余全部成功，没有任何 job 以信号结束。常设崩溃现场采集持续开启。

结论：**停服路径逐字未变，残余风险集合扩大**。理由：崩溃现场位于停服顺序的前段（停止信号、宽限等待、runtime 关闭、`db.close()` 开始到 flush 写文件之前），这段代码、服务生命周期、原生交界与它们依赖的原生库都没有变化；`0.5.0rc1` 的接受已经把「停服窗口内新的在途处理体没有定向压力证据」列为残余风险，本版只是在同一类别里增加了计算代码。上面第 5 项的运行统计只是辅助证据，不说明根因已排除。

**残余风险**（继承后仍然存在，不因本地端到端全套通过而排除）：`0.5.0rc1` 接受的全部残余风险（最终 flush 与打开路径的新代码、导入时调用的 PyO3 配置函数 `configure_flush_budgets`、稀疏与 BM25 检索、写入时生成输出字段、按字节预算的自动 flush 等在途处理体），加上本版新增的三类在途处理体（算术、几何、function chain），都没有托管机器上的定向停服压力证据。下文三组端到端全套各 703 项无跳过，降低了常规停服覆盖的不确定性，但不是定向压力。

**适用范围**：谱系以 D 的 `crates/` 树 `c695221b…` 与 `Cargo.lock`（相对 D 只差三个本项目 crate 的版本）为准，工具链为 Rust 1.98.1，PyO3、tonic、tokio 等停服相关依赖的版本与校验和相对 `0.5.0rc1` 逐字未变，同进程 grpcio 为 CI 固定的 1.84.0。下一个候选以此为基准比较；变化时本接受不再自动适用，须由负责人再次决定。

冻结提交须同时满足以下条件，任何一项不满足即停止候选准备：

1. `crates/` 树与 D 相同（三个 crate 都用 `version.workspace`，版本切换不改 `crates/`）；
2. 相对 D，`Cargo.lock` 只有三个本项目 crate 的版本变化，其余包逐字不变；
3. Rust 工具链为 1.98.1，CI 的 SDK 约束不变；
4. 「相对 `fd70faf` 的核对结果」中的第 1、3、4 项结论在冻结提交上仍然成立。

这是「根因未查明、显式风险接受」，不是修复。候选的任何运行再次出现停服路径 SIGSEGV，立即停止快进与发布并撤回接受，按调查记录的停止条件处理，不重跑掩盖。冻结提交号、负责人的继承确认与上述条件的逐项核对结果写入候选验收记录。
