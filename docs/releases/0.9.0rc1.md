# 0.9.0rc1 发行范围与说明

本文固定本版本的范围、限制与安装说明，作为 GitHub Release 正文的唯一内容来源，不记录随发布推进变化的状态。冻结提交与执行结果由 Release 附件中的候选结果给出，七个附件的哈希由 Release 正文的候选证据一节与链接的候选验收记录给出；是否已发布及公开下载结果以该正文为准。

这是以 Rust 实现的非官方 milvus-lite，与 Milvus／Zilliz 无隶属关系。该版本为预发布试用，不建议用于生产；RC 阶段通过本项目 GitHub Release 分发，不上传 PyPI。以下安装入口须等对应 Release 正式发布后使用。

## 相对 0.8.0rc1 的变化

本版是性能改动加一项后台建图修复。检索结果、过滤语义、距离数值、错误信息与持久化格式都与 `0.8.0rc1` 相同，没有新增与官方 3.x（参照 `1320d26`）的差异；没有新增或升级依赖，工具链不变。`0.8.0rc1` 及更早版本的能力继续保留，见 [0.8.0rc1 发行说明](0.8.0rc1.md)。

性能数据只在原生 x86_64 服务器（AMD EPYC 7702，16 核）上测得，128 维、FLAT L2，aarch64 与 macOS 没有同等测量。

- **大 limit 检索**（[记录](../testing/large-limit-search-performance.md)）：100 万行、nq1000、limit 1000，不含客户端构造结果的部分由约 4.3 s 降到 1.8–1.9 s（2.5.1 为 2.55 s），全程由约 7.0–7.2 s 降到 4.4–4.5 s（2.5.1 为 5.35 s），其中 pymilvus 构造结果约 2.7 s，两方相同；100 万行的改前与 2.5.1 不在同一时段测量。10 万行同一时段交替测量，与 2.5.1 持平。`0.8.0rc1` 登记的「大结果检索比 2.5.1 慢约 35%」对 FLAT 不再成立。常规检索（nq1–100、limit 10–100）持平或略快。3.x 单次约 200 s，未完成测量。未测：nq 很小而 limit 很大（块数降到与线程数相同，并发时单个请求取决于最慢的一块）、IP / COSINE 与其他维度、带过滤或分组的大 limit 检索、HNSW 走图、内存占用。
- **过滤表达式**（[记录](../testing/filter-performance.md)）：100 万行，改前与改后不在同一时段测量。

  | 表达式（count p50，ms） | 改前 | 改后 | 2.5.1 |
  | --- | --- | --- | --- |
  | `name like "n12%"` / `name like "%99"` | 364 / 328 | 12 / 14 | 13 / 126 |
  | `tag in [...]` 50 项 / 5 项 | 87 / 82 | 21.5 / 8.0 | 13–23 / 8–15 |
  | `tag * 3 + 1 > 1500` | 87 | 17 | 不支持 |
  | `(a and b) or c` / 再 `or not (...)` | 203 / 249 | 15 / 20 | 7–9 / 不支持 |
  | `$meta["k"] > 500` / `s == "v7"` | 272 / 231 | 128–135 / 160 | 103 / 110 |
  | Query limit 100，`tag < 500`（宽命中） | 6–10 | 4.7 | 2.5–2.7 |

  未经改动路径的表达式 count 仍在 2–7 ms；其中 `tag < 500` 改后 3.4 ms、改前 1.9–3.5 ms，区分不了时段漂移与小幅回退。本实现改前改后、2.5.1、3.x 的 count 与结果摘要一致（2.5.1 不支持的除外），3.x 慢约 30 倍到近万倍。Query 的快路径要求数据全部已 flush 且各段主键区间按序不重叠，否则走原算法；存活行不足一半（大量删除且尚未合并）时布尔树仍走整源路径，这一场景没有测量。
- **HNSW 重开后不再白建图**：重开数据目录后 load 时，后台维护排出的建图任务会把磁盘上有效的图从头再建一遍；现在先读入有效的图文件，只为缺失或失效的段建图。
- **大 limit 检索期间的公平性（代价）**：有大 limit 批量检索在进行时，后到的单条 top10 检索 p50 由约 18 ms 升到 19–26 ms、p99 由约 21 ms 升到约 28 ms（引擎探针，不经 RPC；100 万行，后台 nq700 × limit 1000），与 limit 10 的大批量检索在进行时同一量级；同一时段内后台检索完成数约为改前的 2.5 倍（[公平性](../testing/large-limit-search-performance.md#公平性)）。

## 兼容性与已知限制

- **降级**：格式没有改动。降级到 `0.8.0rc1`：候选验收在 Linux x86_64 上核验它读取本版写出的目录，降级后写入再升级没有专项实测。降级到 `0.7.0rc1` 及更早：降级前先用本实现正常打开并关闭一次，影响见 [0.8.0rc1 发行说明「兼容性与已知限制」](0.8.0rc1.md#兼容性与已知限制)。
- **仍慢于 2.5.1**：100 万行时，JSON 与动态字段的 count 约为 2.5.1 的 1.25–1.45 倍，`(a and b) or c` 的 count 与 Query 约 2 倍，`in` 50 项的 Query 约 1.7 倍，Query limit 100 的宽命中约 1.8 倍；带过滤的检索中 `$meta["k"] > 500` 与 `(a and b) or c` 反而更快。10 万行时，动态字符串与组合表达式的 count、未经改动路径的 Query 宽命中（2.3–2.6 对 1.6–2.1 ms，[记录](../testing/filter-performance.md#结果10-万行)）、limit 100 的检索（0.25–0.38 对 0.21 s，不含客户端构造结果）仍更慢。
- **停服路径的一次段错误：根因未查明，显式风险接受，不是修复。** 持续集成试点中，Linux x86_64 的一次差分运行在停服路径上出现过一次进程段错误，此后的定向压力、AddressSanitizer 与各次运行都没有再现（[调查记录](../testing/shutdown-segfault-investigation.md)）。本版停服路径的函数没有改动，但建图线程的任务新增「先读入有效图文件」一步，x86_64 的 AVX2 分派新增两个按段打分的函数；这两处与本版的过滤代码都没有定向停服压力证据，也不在 AddressSanitizer 的覆盖内。按调查记录「失效与继承」不继承 `0.8.0rc1` 的接受，由负责人**再次做显式发布级风险接受**，依据见[候选方案](0.9.0rc1-candidate-plan.md#停服段错误再次做发布级风险接受)；候选或后续运行再次出现即撤回，转回根因调查。
- **沿用的限制**：以下各项沿用 [0.8.0rc1 发行说明](0.8.0rc1.md)的「与 3.x 的主要已登记差异」「相对 0.7.0rc1 新拒绝或改变的行为」「兼容性与已知限制」及其链接的 [0.7.0rc1 发行说明](0.7.0rc1.md#兼容性与已知限制)：HNSW 的近似结果、FLAT 回退、后台构建与参数解析差异，HNSW 的性能、建图耗时与内存，写入峰值内存，`malloc_trim` 的代价，稀疏向量检索在 nq 较大时慢于 2.5.1，JSON 写入优化的适用范围，fork 的使用限制，nullable 向量与官方 3.x 的互通限制，批量检索的性能与公平性，jieba 的资源，过滤路线，距离误差预算，Search iterator V1，SDK 端点 schema 缓存，dump。除 HNSW 外，已接受的 ANN 定义不意味着实际 ANN，INVERTED 的执行仍为扫描；存量定义与封锁恢复见 [0014](../decisions/0014-index-definitions-and-filter-expressions.md) 与[兼容性说明](../compatibility.md#索引变更后的人工恢复)。
- LoadPartitions / ReleasePartitions、snapshot RPC、TEXT_EMBEDDING、model rerank、boost 的 `random_score`、`ARRAY<TIMESTAMPTZ>` 与 `ARRAY<GEOMETRY>`、AddCollectionField／AlterCollectionSchema、行级权限 RPC 不在本版范围。

## 平台、解释器与证据边界

四个平台均为标准层，在发行工作流中执行相同的适用门槛（[0021](../decisions/0021-release-build-in-ci.md) 第 9、14–16 条，编排按 [0039](../decisions/0039-release-speedup.md)）：Linux x86_64 与 arm64 在 GitHub 托管机器上固定的 manylinux_2_28 容器（glibc 2.28）中执行，macOS arm64 在 `macos-15`、macOS x86_64 在 `macos-15-intel` 上原生执行。各平台覆盖正式 wheel 的归档与二进制检查、Rust 默认与故障注入构建的单测、CPython 3.10 与 3.15 上两条 SDK（pymilvus 2.6.18／3.0.3）的端到端全套、CPython 3.10 上两条 SDK 的 dump 端到端、3.11–3.14 联合冒烟、正式 wheel 上与官方 3.x（`1320d26`，NumPy 2，参照侧装 jieba 0.42.1）的差分（含 dump）及 Arrow 15/25/26 数据互通，以及故障注入测试包的恢复专项；Linux 另验 LOCK、strace 与容器 PID 1，Linux x86_64 另验已发布 `0.8.0rc1` 读取本版写出的目录。sdist 另验构建根、PEP 517 安装、Rust 1.89 MSRV 与各项构建期拒绝。

过滤的改动另由随机对拍与变异检查覆盖；大 limit 检索的响应字节与改前逐位相同，引擎探针的结果指纹在 x86_64 与 arm64 上都与改前相同。x86_64 的 AVX2 距离核（含本版新增的按段打分函数）与基线版本由逐位比对的单测在支持 AVX2 的执行机上同时执行；托管执行机都支持 AVX2，不支持 AVX2 的 x86_64 CPU 上选用基线版本的分派分支没有端到端证据。

Windows、free-threaded 和非 CPython 在构建时明确拒绝。musl、其它架构及较低 glibc 的自行构建仅为实验性尝试。Linux 容器的宿主内核是托管机器的较新版本，托管机器没有 macOS 11；二进制的最低系统字段由检查核对，不等于真机最低系统、真实断电或任意文件系统持久化已经验证。FI wheel 仅供隔离验收，不随发行分发；本候选不承诺持续维护多个版本线，也不自动将任何 RC 转为正式版。

## 安装（对应 Release 发布后）

本包与官方 milvus-lite 共用 `milvus_lite` 模块，不可同时安装；不用 `pymilvus[milvus-lite]`。

```bash
python -m pip uninstall milvus-lite
python -m pip install pymilvus
python -m pip install --no-index --only-binary :all: --find-links https://github.com/GrittyChen/milvus-lite-rust/releases/expanded_assets/v0.9.0rc1 milvus-lite-rust==0.9.0rc1
```

也可从 [v0.9.0rc1 Release](https://github.com/GrittyChen/milvus-lite-rust/releases/tag/v0.9.0rc1) 下载本平台 wheel 与 SHA256SUMS，核对后安装：

```bash
shasum -a 256 -c --ignore-missing SHA256SUMS && python -m pip install --no-index ./milvus_lite_rust-0.9.0rc1-*.whl
```

Linux 可用 sha256sum 执行同样的校验。需要核对来源时，在下载目录用已登录的 GitHub CLI 执行本平台对应的一行，成功即说明该文件由本仓库的发行工作流签发：

```bash
gh attestation verify milvus_lite_rust-0.9.0rc1-cp310-abi3-manylinux_2_28_x86_64.whl --repo GrittyChen/milvus-lite-rust --signer-workflow GrittyChen/milvus-lite-rust/.github/workflows/release.yml
gh attestation verify milvus_lite_rust-0.9.0rc1-cp310-abi3-manylinux_2_28_aarch64.whl --repo GrittyChen/milvus-lite-rust --signer-workflow GrittyChen/milvus-lite-rust/.github/workflows/release.yml
gh attestation verify milvus_lite_rust-0.9.0rc1-cp310-abi3-macosx_11_0_arm64.whl --repo GrittyChen/milvus-lite-rust --signer-workflow GrittyChen/milvus-lite-rust/.github/workflows/release.yml
gh attestation verify milvus_lite_rust-0.9.0rc1-cp310-abi3-macosx_11_0_x86_64.whl --repo GrittyChen/milvus-lite-rust --signer-workflow GrittyChen/milvus-lite-rust/.github/workflows/release.yml
```

sdist 的 Python 下限及 Rust 1.89 MSRV 沿用 [源码回退门槛](../../tests/packaging/README.md#源码与拒绝门槛)，不引导从 PyPI 按项目名解析本包。dump 需要的 `pymilvus[bulk_writer]` 另行安装，见[使用说明](../usage.md#导出-dump)。
