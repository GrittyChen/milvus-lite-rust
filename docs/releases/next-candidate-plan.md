## 执行顺序

1. 版本与范围已确认。本次版本切换只涉及候选准备，不包含本地提交、推送、tag 或 Release 发布许可。
2. 同步 Cargo / 锁文件版本、README 与元数据中的能力及安装版本，新增对应版本的发行说明。旧版本说明保留历史身份。检查器与测试中的版本约束按实际消费点检查，避免遗漏或全仓替换历史记录。
3. 完成相关打包 / 平台工具自检、默认与完整 FI 编译检查，将版本和文档变更交审阅。审阅通过并获准本地提交后，才以该提交冻结构建输入。这是启动长时间完整矩阵前的明确检查点；未通过或未获准提交时不启动矩阵。记录完整提交、源码归档、新候选输入清单与工具身份；后续改变发行载荷即按 0013 重新冻结和重建。
4. 从该归档顺序构建四个平台的正式 wheel、sdist 与三标准层的隔离 FI wheel；每个平台先完成、收集并校验证据，再回收可再生构建缓存。沿用已有工具链和平台，不把开发 wheel 重命名成新版本。
5. 执行下表及 0013 的完整候选门槛，区分本轮实跑、历史证据及未执行项。保留准备失败、阶段续跑与原始日志；失败不能以单跑成功或放宽断言收口。
6. 交付候选验收记录、统一发行正文、附件哈希与可复验的证据包，交独立评审。通过后再分别处理推送、冻结提交上的 tag 与 Release 发布；公开下载 / 安装验证在发布后执行。
