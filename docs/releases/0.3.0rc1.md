# 0.3.0rc1 发行范围与说明

本文固定本版本的功能范围、限制与安装说明，作为 GitHub Release 正文的内容来源，不记录随发布推进变化的状态。冻结提交、附件哈希和执行结果由对应 GitHub Release 正文链接的候选验收记录给出；是否已发布及公开下载结果以该正文为准。

这是以 Rust 实现的非官方 milvus-lite，与 Milvus／Zilliz 无隶属关系。该版本为预发布试用，不建议用于生产；RC 阶段通过本项目 GitHub Release 分发，不上传 PyPI。以下安装入口须等对应 Release 正式发布后使用。

## 相对 0.2.0rc1 的功能增量

- 显式分区：Create / Drop / Has / Show / GetPartitionStatistics，以及既有 Insert / Upsert / Query / Get / Search 等路径的分区参数。先选择分区再判可见版本，删除按主键全局生效；不增加独立分区 load 状态。
- partition key：非主键 INT64 / VARCHAR 按参照固定哈希路由到 16 桶，另保留 `_default`；Describe、nullable / 默认值、Upsert、恢复与合并一并覆盖。请求的 `num_partitions` 仍按参照忽略，不改变桶数。
- 非 key 同批重复主键 Upsert：每行独立从请求前的旧值合并，不再累计同批前一行的修改。下面列出可观察变化。

已发布 0.2.0rc1 的标量 nullable / 默认值、ARRAY、Query iterator、range search / Search iterator V1 继续保留。实现合同与差异分别见 [0015](../decisions/0015-nullable-defaults-and-array.md)、[0016](../decisions/0016-query-iteration-and-range-search.md)、[0017](../decisions/0017-partitions.md)。参照固定为官方 milvus-lite v3.2.1／`43d1257774e629bc9f66873977ab7c320d5bf5a7`。

## Upsert 行为变化

旧行是 `{id:1,x:0,y:0}`，同一个请求对该主键做 partial Upsert：

```json
[{"id":1,"x":1},{"id":1,"y":2}]
```

已发布 0.2.0rc1 的结果是 `{id:1,x:1,y:2}`；本版变为 `{id:1,x:0,y:2}`，与参照 3.x 一致。第二行从请求前的旧行出发，所以不继承第一行的 `x=1`。如果分成两个先后请求，则仍依次合并，结果为 `{id:1,x:1,y:2}`。普通 Upsert 也按请求前状态独立合并，详见[修复与反证](../testing/0017-non-key-upsert-fix.md)。partition key 的重复主键胜者由实际分桶写入顺序决定，不能概括成输入最后一行总是获胜。

## 兼容性与已知限制

- 沿用 3.x 的 schema.json、Arrow IPC WAL、Parquet 与 manifest format 2 编码，不增加私有数据格式；格式相同不代表旧版本支持新增 schema 或分区语义。
- **降级到已发布 0.2.0rc1**：包含非默认分区的 manifest 或 partition key schema 会使对应 collection 在清理前被明确拒绝，不能降级后继续读写这些集合；拒绝不能改坏受保护文件，同库健康 collection 仍可打开。删除最后一个非默认分区且无 key 等旧版不支持属性时，仅剩 `_default` 的目录可能回到旧版能力范围，不能声称所有新版本目录永久拒绝。更早 0.1.0rc1–rc3 对 nullable / ARRAY 等 schema 属性的拒绝边界继续保留。具体回退用例见 [0017](../decisions/0017-partitions.md)、[0015](../decisions/0015-nullable-defaults-and-array.md)。
- 分区名称、实际目录身份及 snapshot pins 按 0017 的安全合同检查，路径越界、符号链接及物理目录别名被拒绝；Drop 保留其它分区仍需的全局删除记录，避免重开后已删除行复活。这些是相对参照缺陷的显式差异。
- partition key 的 B1 / B2 / B3 差异继续披露：生成 ID 取分桶后行 seq，按原输入顺序返回，可能为 `[1,3,2]`；所有桶的确定性校验 / 转换完成后才追加 WAL；自动 ID 将覆盖请求前可读旧行时整批拒绝。显式覆盖仍允许；真实 WAL I/O 故障仍按既有已校验前缀协议恢复，不承诺整批原子写入。
- 过滤继续按参照的整条表达式路线执行，缺失值、null、短路及类型错误依路线而异。算术、时间与几何谓词仍为范围外。
- JSON 顶层标量及相应默认值沿用 0004 已登记的任意 JSON 值规则，存在参照 Arrow 转换缺陷对应的差异；非有限数值与 binary 原始默认值暂不支持，超出参照默认数字位数限制的数值也明确拒绝，具体边界见 0015。
- 距离沿用 [0004](../decisions/0004-m1-scope.md) 的浮点误差预算；范围阈值落在误差带内时，两端可能有成员或数量差异。服务端仍作严格比较，不加 epsilon；带外结果不得以该规则豁免。
- Search iterator V1 依赖 SDK 的有限探测算法，部分批量和距离分布下会提前结束；不保证任意数据下完整遍历。服务端忽略 V2 探测参数，返回不含 V2 字段的普通结果，SDK 据此自动回退 V1，与参照一致；服务端 V2、token 和跨请求 MVCC 未实现。
- 手写 proto 中，被同名后列覆盖或被完整布局 valid_data 掩码遮住的坏 JSON 仍会被拒绝；相对 rc3 的严格化边界及理由见 [0015](../decisions/0015-nullable-defaults-and-array.md)。普通 SDK 不构造这类请求。
- 两条 SDK 的端点 schema 缓存限制仍存在：同一进程中，显式释放后复用端口，或 CLI 在固定端口更换数据目录重启，可能使 SDK 沿用旧 schema。此问题在真实 3.x 上也存在；测试的跨用例隔离没有修改 SDK 或产品运行行为，见[调查与反证](../testing/0015-0016-cross-platform-acceptance.md#本轮发现两条-sdk-的跨用例-schema-缓存污染)。
- 向量仍仅以 FLAT 执行，已接受的 ANN 定义不意味着实际 ANN；新建 INVERTED 只接受 BOOL、INT8/16/32/64、FLOAT/DOUBLE、VARCHAR，执行仍为扫描；JSON／ARRAY 新定义被拒绝，存量 ARRAY 定义在需要构建时按参照报错。存量定义、DropIndex 及持久化未确认时的封锁／恢复沿用 [0014](../decisions/0014-index-definitions-and-filter-expressions.md) 和 [README](../../README.md)。
- LoadPartitions / ReleasePartitions、alias／rename、snapshot RPC、稀疏向量、BM25／function chain、nullable 向量、真实 ANN、TIMESTAMPTZ／GEOMETRY、AddCollectionField／AlterCollectionSchema 不进入本次新增范围。
- JSON 写入及进程峰值资源相对参照 3.x 的差距继续单独跟进，本次未解决，也不新增性能提升承诺。详见 [B 性能边界](../testing/0017-partition-key-performance.md)。

## 平台、解释器与证据边界

沿用 [0013](../decisions/0013-first-release-platform-and-packaging.md)：Linux x86_64／arm64 的 glibc 2.28，macOS arm64 最低版本字段为 11.0；macOS x86_64 只要求构建与两个解释器端点的冒烟，实际原生或 Rosetta 方式须在最终验收中注明。GIL CPython 验证窗口为 3.10–3.15，两条 SDK 固定为 pymilvus 2.6.17／3.0.2。

Windows、free-threaded 和非 CPython 在构建时明确拒绝。musl、其它架构及较低 glibc 的自行构建仅为实验性尝试；容器运行和二进制系统下限字段不等于真机最低系统、真实断电或任意文件系统持久化证明。

[开发跨平台验收](../testing/0017-cross-platform-acceptance.md)已经复审通过；版本与文档须先审阅并获准本地提交，随后从冻结提交构建并按 0013 验收，开发结果不替代最终产物的证据。最终附件为四个平台的正式 wheel、sdist 与覆盖这些附件的 SHA256SUMS；FI wheel 仅供隔离验收，不随发行分发。

旧线是否继续发修复版按实际需求另定；本候选不承诺持续维护多个版本线，也不自动将 0.1 或 0.2 转正式版。

## 安装（对应 Release 发布后）

本包与官方 milvus-lite 共用 `milvus_lite` 模块，不可同时安装；不用 `pymilvus[milvus-lite]`。

```bash
python -m pip uninstall milvus-lite
python -m pip install pymilvus
python -m pip install --no-index --only-binary :all: --find-links https://github.com/GrittyChen/milvus-lite-rust/releases/expanded_assets/v0.3.0rc1 milvus-lite-rust==0.3.0rc1
```

也可从 [v0.3.0rc1 Release](https://github.com/GrittyChen/milvus-lite-rust/releases/tag/v0.3.0rc1) 下载本平台 wheel 与 SHA256SUMS，核对后安装：

```bash
shasum -a 256 -c --ignore-missing SHA256SUMS && python -m pip install --no-index ./milvus_lite_rust-0.3.0rc1-*.whl
```

Linux 可用 sha256sum 执行同样的校验。sdist 的 Python 下限及 Rust 1.89 MSRV 沿用 [源码回退门槛](../../tests/packaging/README.md#源码与拒绝门槛)，不引导从 PyPI 按项目名解析本包。
