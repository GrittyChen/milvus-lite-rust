# 0.5.0rc1 发行范围与说明

本文固定本版本的范围、限制与安装说明，作为 GitHub Release 正文的唯一内容来源，不记录随发布推进变化的状态。冻结提交与执行结果由 Release 附件中的候选结果给出，七个附件的哈希由 Release 正文的候选证据一节与链接的候选验收记录给出；是否已发布及公开下载结果以该正文为准。

这是以 Rust 实现的非官方 milvus-lite，与 Milvus／Zilliz 无隶属关系。该版本为预发布试用，不建议用于生产；RC 阶段通过本项目 GitHub Release 分发，不上传 PyPI。以下安装入口须等对应 Release 正式发布后使用。

## 相对 0.4.0rc1 的变化

参照由 v3.2.1／`43d1257` 升级为官方 milvus-lite `1320d26ec3d88b23b525e774df6e3c8e7c208f81`（v3.2.2 之后 3 个提交），本版按它对齐，与参照的逐项差异登记在 [0006 差异表](../decisions/0006-m2-scope.md#与-3x-的差异)。新增四组对外能力：

- **`text_match` 与分析器属性**（[0029](../decisions/0029-text-match.md)）：`text_match(field, 'query')` 按 3.x 的 standard 分词，可用于 Query、Search、count、Delete、boost 与 HybridSearch；`enable_analyzer`、`enable_match`、`analyzer_params` 可以建表、回显并与 3.x 互通。
- **稀疏向量**（[0030](../decisions/0030-sparse-vectors.md)）：`SPARSE_FLOAT_VECTOR` 字段的写入、读回与输出，`SPARSE_INVERTED_INDEX` + IP 的定义、load 与检索；倒排在首次检索时按 segment 构建并缓存，不写索引文件。
- **全文检索（BM25）**（[0031](../decisions/0031-bm25.md)）：BM25 function 在写入时由开启 `enable_analyzer` 的 VARCHAR 字段生成稀疏输出字段；`SPARSE_INVERTED_INDEX` + BM25 与以文本为查询的检索，分数按 segment 统计，对外距离是负数、越小越相关，与 NumPy 2 环境中的 3.x 逐位一致。
- **多向量字段**（[0028](../decisions/0028-multi-vector-fields.md)）：一个集合可以有多个 FLOAT_VECTOR 字段，索引与度量按字段，HybridSearch 每一路用自己的字段。

另有两项修复：自动 flush 改为按字节预算触发（[0027](../decisions/0027-reference-3.2.2-upgrade.md#第-2-步flush-字节预算)），修复反复改写少量主键时 WAL 与内存无界增长；JSON 文本解析不再把首键为 `$serde_json::private::Number` 的用户对象当作数字（[修复记录](../testing/json-private-number-key-fix.md)），此前这类值会被静默改写、误拒，或让集合在 flush 与重开时失败。

没有新增或升级依赖，Rust 1.98.1 工具链不变。`0.4.0rc1` 及更早版本的能力（集合管理与多数据库、分组检索、TIMESTAMPTZ 与 `timezone`、HybridSearch 与 rerank、显式分区与 partition key、nullable / 默认值、ARRAY、Query iterator、range search / Search iterator V1、JSON 写入优化）继续保留，见 [0015](../decisions/0015-nullable-defaults-and-array.md)–[0018](../decisions/0018-json-write-normalization.md)、[0023](../decisions/0023-aliases-rename-truncate-databases.md)–[0026](../decisions/0026-rerank-and-hybrid-search.md)。

## 与 3.x 的主要已登记差异

完整清单与理由见 [0006 差异表](../decisions/0006-m2-scope.md#与-3x-的差异)，下面只摘要本版新增的部分：

- **自动 flush 的位置**：按与 3.x 相同的预算触发，但不保证逐字节同一位置（WAL 取实际写出的字节，小批量时比 3.x 更早触发），segment 布局因此可能不同。
- **`text_match` 与分析器属性**：分词器固定 standard；大小写与 `\w` 的判定固定用 CPython 3.12 / Unicode 15.0 的表，不随运行的 Python 版本变化；含 `NaN`、`Infinity`、`1e999` 这类溢出数、孤立代理或嵌套超过 124 层的 `analyzer_params` 建表返回 UNIMPLEMENTED，3.x 写出的含 `NaN`、`Infinity`、`1e999` 或超过 124 层 `analyzer_params` 的 `schema.json` 让该集合打不开（可以 drop）；JSON 字段的顶层字符串本实现存带引号的 JSON 文本（3.x 存解码后的文本），`text_match`、`==`、`like` 等按存储文本的整字段操作结果因此不同。完整列表见 [0029「登记的差异」](../decisions/0029-text-match.md#登记的差异)。
- **稀疏向量**：带稀疏默认值的集合打开时报错（可以 drop）；nullable 稀疏列有空值时按紧凑格式输出，pymilvus 读出真实值；原始 gRPC 把稀疏数据写进 JSON 字段、动态字段里的稀疏值带 NaN / Inf 时拒绝；指定其他分区、尚未 flush 的删除在稀疏检索中立即全局生效。
- **BM25**：jieba 分词器返回 UNIMPLEMENTED；NumPy 1 环境中 3.x 的分数按 float64 计算，与本实现差若干 ULP；segment 布局不同时统计不同，分数与次序随之不同（需要逐位对齐时用显式 flush 控制布局）；分数为 NaN 时结果集合与次序可能不同；调参项与函数参数里的 `NaN` / `Infinity` / `-Infinity` 返回 UNIMPLEMENTED；标了 `is_function_output` 却没有函数产出的非稀疏字段（只有原始 RPC 能建出）建表返回 UNIMPLEMENTED，3.x 的这种集合打不开（可以 drop）。TEXT_EMBEDDING function 不支持。
- **多向量字段**：第二个及之后的向量字段缺失或为 None 时拒绝写入（3.x 写入成功，flush 后读取出错）；原始 RPC 里非首向量字段的数据不是向量类型时报 `vector field '<字段>' must be list/tuple, got <类型>`（code 6，3.x 为 Arrow 内部文案）；已含 null 向量行的 3.x 目录，该集合无法打开。与 3.x 一样，`drop_index` 传字段名时删除全部索引：在多向量集合上删 `v2` 也会删掉 `v1` 的索引，`v1` 的默认度量随之回到 COSINE；用 `<字段名>_idx` 或显式的 `field_name` 才定向删除。
- **WAL 中的 null 行**：3.x 写出的、非空列含 null 的 WAL 批次让该集合打开失败，不再按截断丢弃这一批及其后的写入。

## 相对 0.4.0rc1 新拒绝或改变的行为

- **Search / HybridSearch 的主键投影**：主键始终在结果的 `id` 中，但只有显式请求或 `*` 时才出现在 `entity` 与 `output_fields` 里。依赖 `hit["entity"]` 含主键的代码需要显式请求主键。Query / Get 不变。
- **度量**：请求与 CreateIndex 的度量转大写后比较，小写的 `ip`、`cosine` 现在可用；空串与 JSON `null` 等同未传；非字符串报 `metric_type must be a string`（code 6）。请求未带度量时取目标字段索引的度量，没有索引度量时仍取 COSINE；索引度量为 BM25 / NONE 时报错（此前回退到 COSINE）。未知度量报 code 6，`field '<字段>': unsupported dense metric '<大写后的值>'`。
- **带 `partition_names` 的无过滤 `count(*)`**：按去重后的分区逐个求和（同一主键跨分区时重复计入），不检查 load；分区不存在时 code 200。此前返回全集合行数。这一行为来自参照 `1320d26` 的修复，与 PyPI 上已发布的 3.2.2 不同。
- **自动 flush**：不再按 1 万行触发，改为每个集合的 MemTable 保留字节达到 128 MiB 或未提交的 WAL 达到 256 MiB 时触发；这是每个集合的 flush 时机，不是进程内存上限；与此前相比，每个集合在内存中保留的数据可能更多（[0027 基线对照](../decisions/0027-reference-3.2.2-upgrade.md#基线对照)中 10 万行时 flush 后服务 RSS 多约 158 MiB）。两个阈值可由环境变量 `MILVUS_LITE_MEMTABLE_MEMORY_LIMIT_BYTES`、`MILVUS_LITE_WAL_SIZE_LIMIT_BYTES` 设置（单位字节），在导入 `milvus_lite` 时读取一次；值不是正整数时导入抛 `ValueError`，pymilvus 打开本地 `.db` 随之失败。
- **打开时修复积压**：打开集合时，若旧版本留下的 WAL 或回放后的 MemTable 已超过预算，在提供服务之前先 flush 一次，因此恢复时最多回放约 256 MiB 的 WAL；这次 flush 失败时打开失败，下次访问重试。
- **首键为 `$serde_json::private::Number` 的 JSON 对象**按普通对象保存、读回与过滤，此前被当作数字或拒绝。旧版本写入前已被改成数字或丢弃的值（JSON 字段值、索引参数等）无法恢复，见[修复记录「已有数据」](../testing/json-private-number-key-fix.md#已有数据)。
- **WAL 中非空列含 null 的批次**（只有 3.x 的缺陷会写出）让该集合打开失败，此前按截断处理、丢弃这一批及其后的写入，见上一节。
- **原先失败的请求现在执行**：上面四组能力原先返回 UNIMPLEMENTED，带这些 schema 的 3.x 集合原先打不开；boost 过滤里的 `text_match` 原先返回 UNIMPLEMENTED。依赖这些请求必然失败的调用方需要调整。

## 兼容性与已知限制

- **数据格式**：数据文件沿用 schema.json、Arrow IPC WAL、Parquet 与 manifest format 2 编码，不增加私有数据格式；稀疏向量与 BM25 输出列按 3.x 的打包字节存储，倒排不落盘。已发布的 `0.4.0rc1` 读取本版写出的普通与 partition key 集合目录，partition key 集合再由本版重开核对旧版的追加，由候选验收在 Linux x86_64 上核验。
- **降级到 0.4.0rc1 及更早**（macOS arm64 实测）：
  - 普通与 partition key 集合（只在 WAL、已 flush、flush 后删除并追加三种状态）可以正常读写，再升级回来数据完整。
  - 有多个向量字段、含稀疏向量字段、带 BM25 function、带 `enable_analyzer` / `enable_match` / `analyzer_params` 任一属性的集合，在旧版 load 时明确返回 UNIMPLEMENTED，可以 drop（报错分别为 `multiple vector fields`、`has dtype "sparse_float_vector"`、`schema functions`、`has unsupported attributes`），数据保留，升级回来后照常可用。
  - 降级到 `0.3.0rc3` 及更早的拒绝边界（非默认数据库、TIMESTAMPTZ、带 `timezone` 属性的集合、别名，以及改名与清空意图须先收尾）继续适用，见 [0.4.0rc1 发行说明](0.4.0rc1.md#兼容性与已知限制)；更早版本的边界见 [0017](../decisions/0017-partitions.md)、[0015](../decisions/0015-nullable-defaults-and-array.md)。
- **停服路径的一次段错误：根因未查明，显式风险接受，不是修复。** 持续集成试点中，Linux x86_64 的一次差分运行在停服路径上出现过一次进程段错误；此后 valgrind 检查与停服时序定向压力（合计 41568 轮）都没有再现，此后的运行中也没有再现（检索范围见候选方案）。本版相对上一次接受有变化：停服顺序本身与相关原生依赖不变，变化的是最终 flush、打开路径与停服时可能在途的请求处理中的安全 Rust 代码，以及导入时执行一次的一个绑定函数；这些新代码没有托管机器上的定向压力证据。本版据此**再次**做显式发布级风险接受，适用范围与依据见[候选方案](0.5.0rc1-candidate-plan.md#停服段错误再次做发布级风险接受)；候选或后续运行再次出现即撤回这一接受，转回根因调查（[调查记录](../testing/shutdown-segfault-investigation.md)）。
- 过滤继续按参照的整条表达式路线执行，缺失值、null、短路及类型错误依路线而异。算术（时间戳加减区间除外）与几何谓词仍为范围外。
- 距离沿用 [0004](../decisions/0004-m1-scope.md) 的浮点误差预算；范围阈值落在误差带内时，两端可能有成员或数量差异。BM25 与稀疏 IP 的分数按 3.x 逐位对齐，不使用这一误差预算。
- Search iterator V1 依赖 SDK 的有限探测算法，部分批量和距离分布下会提前结束；服务端忽略 V2 探测参数，SDK 据此自动回退 V1，与参照一致。
- 两条 SDK 的端点 schema 缓存限制仍存在：同一进程中显式释放后复用端口，或 CLI 在固定端口更换数据目录重启，可能使 SDK 沿用旧 schema；真实 3.x 上同样存在。
- 向量仍仅以 FLAT 执行，已接受的 ANN 定义不意味着实际 ANN；INVERTED 定义的执行仍为扫描。存量定义、DropIndex 及持久化未确认时的封锁与恢复沿用 [0014](../decisions/0014-index-definitions-and-filter-expressions.md) 和 [README](../../README.md)。
- LoadPartitions / ReleasePartitions、snapshot RPC、jieba、TEXT_EMBEDDING、公共 function chain、model rerank、nullable 向量、真实 ANN、GEOMETRY、AddCollectionField／AlterCollectionSchema 不在本版范围。
- 稀疏向量检索在 nq 较大时仍慢于 2.5.1（[0030 验收](../decisions/0030-sparse-vectors.md#验收)中 nq=32 约慢 27%），单条查询与过滤检索追平或更快。
- JSON 写入优化的收益限于 [0018 已审同机工况](../testing/0018-json-write-acceptance.md)，不外推为任意 JSON、并发吞吐或全部写入路径的保证；进程峰值资源差距尚未解决，继续单独跟进。

## 平台、解释器与证据边界

四个平台均为标准层，在发行工作流中执行相同的适用门槛（[0021](../decisions/0021-release-build-in-ci.md) 第 9、14–16 条）：Linux x86_64 与 arm64 在 GitHub 托管机器上固定的 manylinux_2_28 容器（glibc 2.28）中执行，macOS arm64 在 `macos-15`、macOS x86_64 在 `macos-15-intel` 上原生执行。各平台覆盖正式 wheel 的归档与二进制检查、Rust 默认与故障注入构建的单测、CPython 3.10 与 3.15 上两条 SDK（pymilvus 2.6.17／3.0.2）的端到端全套、3.11–3.14 联合冒烟、正式 wheel 上与官方 3.x（`1320d26`，NumPy 2）的差分及 Arrow 15/25 数据互通，以及故障注入测试包的恢复专项；Linux 另验 LOCK、strace 与容器 PID 1，Linux x86_64 另验已发布 `0.4.0rc1` 读取本版写出的目录。sdist 另验构建根、PEP 517 安装、Rust 1.89 MSRV 与各项构建期拒绝。

Windows、free-threaded 和非 CPython 在构建时明确拒绝。musl、其它架构及较低 glibc 的自行构建仅为实验性尝试。Linux 容器的宿主内核是托管机器的较新版本，托管机器没有 macOS 11；二进制的最低系统字段由检查核对，不等于真机最低系统、真实断电或任意文件系统持久化已经验证。

FI wheel 仅供隔离验收，不随发行分发。旧线是否继续发修复版按实际需求另定；本候选不承诺持续维护多个版本线，也不自动将任何 RC 转为正式版。

## 安装（对应 Release 发布后）

本包与官方 milvus-lite 共用 `milvus_lite` 模块，不可同时安装；不用 `pymilvus[milvus-lite]`。

```bash
python -m pip uninstall milvus-lite
python -m pip install pymilvus
python -m pip install --no-index --only-binary :all: --find-links https://github.com/GrittyChen/milvus-lite-rust/releases/expanded_assets/v0.5.0rc1 milvus-lite-rust==0.5.0rc1
```

也可从 [v0.5.0rc1 Release](https://github.com/GrittyChen/milvus-lite-rust/releases/tag/v0.5.0rc1) 下载本平台 wheel 与 SHA256SUMS，核对后安装：

```bash
shasum -a 256 -c --ignore-missing SHA256SUMS && python -m pip install --no-index ./milvus_lite_rust-0.5.0rc1-*.whl
```

Linux 可用 sha256sum 执行同样的校验。需要核对来源时，在下载目录用已登录的 GitHub CLI 执行本平台对应的一行，成功即说明该文件由本仓库的发行工作流签发：

```bash
gh attestation verify milvus_lite_rust-0.5.0rc1-cp310-abi3-manylinux_2_28_x86_64.whl --repo GrittyChen/milvus-lite-rust --signer-workflow GrittyChen/milvus-lite-rust/.github/workflows/release.yml
gh attestation verify milvus_lite_rust-0.5.0rc1-cp310-abi3-manylinux_2_28_aarch64.whl --repo GrittyChen/milvus-lite-rust --signer-workflow GrittyChen/milvus-lite-rust/.github/workflows/release.yml
gh attestation verify milvus_lite_rust-0.5.0rc1-cp310-abi3-macosx_11_0_arm64.whl --repo GrittyChen/milvus-lite-rust --signer-workflow GrittyChen/milvus-lite-rust/.github/workflows/release.yml
gh attestation verify milvus_lite_rust-0.5.0rc1-cp310-abi3-macosx_11_0_x86_64.whl --repo GrittyChen/milvus-lite-rust --signer-workflow GrittyChen/milvus-lite-rust/.github/workflows/release.yml
```

sdist 的 Python 下限及 Rust 1.89 MSRV 沿用 [源码回退门槛](../../tests/packaging/README.md#源码与拒绝门槛)，不引导从 PyPI 按项目名解析本包。
