## 必须保留的行为

1. **先选分区，再在候选中去重，再过滤。** 同一主键在同一个活跃 MemTable 跨分区写入，后者全局覆盖前者；但 p1 的旧值已在 segment、p2 写新值时，只选 p1 仍可看到旧值。全集只见新值，分区计数之和可以大于全集。合并不能按全集有效位丢弃 p1 旧值。
2. **删除按主键全局生效，但活跃 tombstone 可以被后续插入移除。** 指定 p1 删除仅存在于 p2 的主键，参照仍返回删除 1 并隐藏 p2。分区参数决定删除记录落点，不把删除变成分区隔离。`p1 旧行 Flush → Delete 未 Flush → p2 同键重插` 会移除 MemTable 的该键 tombstone，使 p1 旧行重新可见；若 Delete 已 Flush，committed-delete 继续隐藏旧行。不能把两者合为只增不减的删除上限。保留严格 `delete_seq > data_seq` 和故障目录中的既有平局规则；两支固定为 [组件真值](../../tests/compatibility_audit/fixtures/partition_visibility_v321.json)。
3. **顺序来自数据源。** 普通 Query 及等距离 Search 保留参照 segment 缓存的遍历顺序，既不是请求中的分区顺序，也不是每次按分区名排序。运行中新增 segment 追加到缓存；重开按 manifest JSON 的分区键序及各文件列表重建。参照保存 JSON 会排序键，所以重开可以改变普通 Query 和等距离顺序。交错写 z、a、z 的补测已覆盖；稳定 SourceId 与展示顺序必须分开。Get 的请求顺序、重复主键及 iterator 的主键排序继续沿用 0016。
4. **保留失败副作用和分派顺序。** Drop unknown 在 Flush 前报错；Drop `_default` 先 Flush 待写数据，再报 code 6。空表达式 count(*) 继续忽略分区和 load；其余 load、表达式、投影、原始列解码的错误优先级不提前。未知分区统计为 200/200，未知集合为 100/4；Show 按名称排序并过滤未知请求名，百分比来自 collection 的 load 状态。
5. Upsert 的全局旧值查找、partial 合并、nullable / ARRAY、三条过滤路线、已登记的 JSON 拒绝边界、range 候选窗和误差预算均沿用已收口合同。实现前对这些与分区交叉的输入补差分，不能只测新 RPC。

## 建议登记的差异

以下 A 的处理方向随设计评审通过；精确诊断与产品行为仍须实施验收。B 的三项方案已由负责人采纳，完整合同仍须单独评审。理由是防止越界写、误删和已删除数据复活，不把参照缺陷伪装为兼容行为。

| 边界 | 参照实测 | 建议行为与影响 |
| --- | --- | --- |
| 空名、`.`、`..`、绝对路径、斜杠、反斜杠、NUL、内部 `_all` | 多数可登记；绝对路径写出 collection，`.` / `..` 可删除其它数据；NUL 先登记后失败 | Create 在任何持久化变更前拒绝，拟用 code 6；安全名称的普通错误仍与参照一致。`_default` 保持重复分区错误。Unix 的反斜杠和 `_all` 原可接受，也明确属于本差异 |
| 物理目录别名或符号链接 | macOS 的 p1/P1、NFC/NFD 同目录；Drop 后重开丢行；符号链接目标被写入并删除 | 新建、加载及维护均验证单个安全目录组件和实际目录身份；拒绝已有分区或 snapshot 钉住名称的物理别名，拒绝链接链；Linux 真实不同的 p1/P1 仍允许，不统一转小写或正规化 Unicode |
| 创建目录失败 | NUL / 超长名报 code 1 后 Has 仍为 true | 先准备目录，再提交 manifest；失败不登记。超长名不另设按字符计数的通用上限；保留真实 I/O 错误类别，避免限制合法 Unicode 名称 |
| Drop 分区丢失全局 delta | 删除已落 p1，数据在 p2；Drop p1 后缓存隐藏，重开复活 | Drop 提交时把仍引用的 delta 保留到 `_default`，删除结果跨重开一致；这是相对参照的有意差异，覆盖跨分区 Delete + Drop + 重开/合并 |
| key 分桶 auto_id 的 WAL 前缀 | 首桶持久化后退出，重开会复用已有 ID 并覆盖行 | 负责人已采纳 B1/B3：新生成 ID 取分桶后行 seq，并拒绝自动主键覆盖可读旧行；完整合同见下文 B 章节。早期“分组前分配”的方向已由真值修订 |

合法 Unicode、冒号等普通 Unix 名称无需一概禁止；名称安全判断属于引擎，adapter 只翻译。Has / Show / Query 对未知名字如果只查表，不额外做路径校验而改变正常的未知名称语义。危险名字的确切诊断文本在 A 实施前作为差异 fixture 固定。

已有 3.x 目录若含危险名、别名或链接，按 collection 明确拒绝，**在任何 WAL 回放写入、残留清理或 GC 之前完成预检**；不重命名、不自动修复，拒绝后同库健康 collection 仍可读取。目录身份检查包含已钉住但未在当前 manifest 注册的分区。进程外绕过 LOCK 同时修改目录不在保证内；仍须拒绝启动时已有的链接，不能把 LOCK 当作路径验证。

## 可见性组件方案

设计时的恢复、runtime、compaction 和文件映射都限定 `_default`；[Visibility](../../crates/core/src/storage/visibility.rs) 只有全集 winner 和位图。给现有位图附加 partition 条件会漏掉被其它分区遮住的行，不能采用。

建议扩展现有组件，维持三类状态：

- 活跃 MemTable 仍是全局主键表。被另一分区覆盖后，原活跃行退出候选；冻结时只输出这一代真实存活的行，不能因分区化恢复被覆盖值。
- 持久化 / 冻结源保留分区身份和每分区的最新候选位置。写入、覆盖、发布、恢复及合并时更新位置索引及 COW 位图；移走活跃 winner 时能回到该分区仍存在的旧 segment，而不是回到已被 MemTable 覆盖的旧槽位。
- 独立 committed-delete 表保持全局，和候选数据同一快照发布；活跃 tombstone 另存并允许在新插入时移除，移除后重新计算受影响主键在各分区的位图。冻结中的删除属于尚未提交的独立代，不能因活跃代同键插入而提前清掉；提交/失败时的代际责任仍按 0007/0011。WAL 删除落点只用于持久化，不限制删除作用域。

全集继续直接读当前全局有效位图；单分区直接读该分区位图。多分区子集不能在每个 RPC 扫描行或遍历全部主键重新判版本：建议在写侧维护**仅有跨分区重复键时才出现的遮挡位图**，记录 p 的候选中哪些被 q 的较新候选遮挡。选择集合 S 时，对每个选定 p，使用本地有效位 AND NOT（所有选定 q 的遮挡位 OR）；之后交给原列式过滤/检索。比较 `_seq`、平局及删除都在更新侧完成。不得缓存全部 `2^P` 种选择集，也不为无跨分区重复键分配空的成对位图。

这个方案的代价必须显式验证：同一键出现在 P 个分区时，遮挡关系最坏为 O(P²)，不能声称只有 O(P) 内存。按有实际重叠的源块稀疏保存，COW 快照不复制列数据；先用组件模型验证无重复、全重复和高分区数的内存与更新成本。如成本不成立，先回到本文修改设计，不能在产品读取中降级为逐行全库有效性判断。第一项实现交付是这部分组件模型及与参照的状态矩阵，不先铺 RPC。

普通读取的源顺序沿用独立 source_order：Flush 按参照发现新文件的顺序追加；合并/Drop 去掉旧源并按参照刷新顺序加入新源。恢复需保留输入 JSON 分区键序，不能依赖 BTreeMap 的排序副作用；写出的 manifest 仍沿用现有排序编码，不加入持久化顺序字段。过滤、排序、距离计算与物化继续在状态锁外使用不可变快照。

## 文件与提交协议

不引入新格式：schema.json 沿用参照已有字段；manifest 仍为 format 2；WAL 已有 `_partition` 扩展为已验证分区名，保留参照每批单一分区及 `_all` 删除语义；Parquet 不新增 `_partition` 列，归属仍来自路径。文件/索引映射从相对文件名扩为 `(partition, relative_file)`，避免同名不同分区冲突。索引侧车、删除意图、钉住引用和恢复预检均一起扩展，不仅修改数据路径。索引意图持久化和重开时的可信缓存边界均取 collection 与本次实际涉及文件的父索引目录，不依赖无关的 `_default/indexes` 是否存在；内核启动来源及文件系统白名单沿用 0014。

### Create / Drop

Create/Drop 直接取得 0007 数据库写入闸门的**独占许可**，覆盖目标检查、必要的 Flush、文件准备、manifest 提交和内存发布全过程，不从共享许可升级。普通 Insert/Delete 持共享许可，必须等待独占操作退出；反向交错时 Create/Drop 也须等待已进入的写者。随后按既有顺序取得 collection.flush_lock、状态锁，不新增锁层级；不能只靠 flush_lock 阻止 Insert/Delete。I/O 不持有状态锁，内部 Flush 使用已经持有的许可，不再递归取得共享许可。Db drop/close 闸门继续覆盖这些操作；检索叶子任务仍不拿锁。实施验收使用确定事件分别暂停检查、Flush、提交及发布阶段，验证两种交错和失败退出后的许可释放。

首次懒打开 collection 的内部路径同样复用已经持有的独占许可，不能调用会再次取得共享许可的普通入口；也不能在持独占许可时等待尚需共享许可才能启动的后台维护。已进入的维护先由闸门等待完成，新到的维护排在闸门之外；同步 Flush 由许可持有者沿既有 flush_lock 路径完成。验收另固定“未打开 collection”及“后台维护已排队”两种交错，防止许可说明正确但内部调用递归死锁。

Create 在安全预检后准备目录和必要的目录 fsync，再提交候选 manifest，最后发布内存状态。目录物化后、任何候选 manifest 提交前，再按完整候选命名空间（含 snapshot pins）检查物理身份：已登记但尚未物化的目录也可能此时显现大小写或 Unicode 别名。拒绝时仅删除本次新建的空目标目录并同步父目录，不递归回收、不删除复用目录或钉住文件；清理失败随原错误上报。若同名旧目录保存 snapshot 钉住文件，允许安全地复用目录，但不能覆盖其中任何文件；物理别名或不可信残留明确拒绝。提交前失败只留下可识别的未引用准备目录；清理不得删去钉住文件。未登记目录不等于整体归引擎所有：其 data/delta 只回收符合现有存储输出命名的孤儿，未知文件保留；不能把 Create 已拒绝的不可信残留经其它分区的 Drop 顺带删掉。

Drop 先按参照检查目标并 Flush 所有待提交代。若恢复已滤掉全部旧 WAL 行，仍须在移除分区引用之前冻结一个空恢复代，沿既有文件同步、manifest 提交、前缀 WAL 清理协议排空继承 WAL；任一步失败都阻止 Drop 提交，重试仍经同一协议。普通空 Flush 和索引重提交继续保持 0007 的既有行为；不放宽未知 WAL 分区的拒绝。之后再执行：

1. 保留旧 manifest 和不可变读取快照；收集目标分区全部引用的 delta，保守转存到 `_default`，不做逐主键最小化优化。
2. 写出同格式、同内容的不可变 delta，fsync 文件与目录；已引用文件或 snapshot 钉住名字绝不覆盖；经过完整预检的未引用孤儿沿用既有清理规则。碰撞沿用既有序号范围文件名机制：保持真实下界，只可保守扩大文件名上界以避让，不改变记录 `_seq`，不推进 manifest.current_seq 作为预留水位。恢复仍按既有 0007 的 `max(manifest.current_seq, 已回放 WAL 的最大 seq) + 1` 分配，不从文件名扩大上界预留 `_seq` 或 auto_id；较大上界只推迟 GC，不能提前 GC。此前草案所称“恢复的文件名高水位规则”是事实性误写，在实施核对时更正，未改变恢复合同。
3. **同一次 manifest 提交**中加入 `_default` 的转存引用并删除目标分区；不能先删分区再单独补 delta。原文件在提交前仍有效，转存副本在提交前只是 orphan。
4. 发布同代数据源、全局删除表和位图；再回收未被 snapshot 钉住的旧文件。失败于 replace 之前与之后的责任、目录 fsync 不确定时的写封锁沿用 0007；不能错误返回成功或回滚到已经失效的旧状态。

补测的数据原型确认 Arrow 15/25 的真实 3.x 能读取转存 delta，重开与实际合并后不复活。原型没有并发、故障注入或碰撞，不证明以上生产提交协议已实现。

### Flush / 合并 / GC / snapshot

恢复继续沿用 0007 已登记的逐主键已提交序号保护：安全名称的过期 WAL 行先按既有规则忽略，实际需要回放的行才要求其分区仍在 manifest 注册。危险名称即使出现在过期行中也拒绝；不会为未知分区创建目录。这不把 3.x 在故障目录中的旧 WAL 覆盖缺陷重新引入。

Flush 先完整校验和转换，再按分区输出；同代的多个输出必须在同一 manifest 状态中发布，仍以 WAL 保留和已校验前缀负责失败恢复。异步冻结不能扩大参照本来已覆盖的活跃 MemTable 候选；并发写、覆盖和分区 Drop 必须进入组件状态矩阵。

合并只在一个分区内部选择文件、去重及重映射；不能用全集 winner 删除在单分区仍可见的旧行。tombstone GC 的最小数据序号从**全部当前分区**计算，转存到 `_default` 不改变删除的全局语义。删除当前分区不移除其它分区的候选；删除全局新 winner 后可能重新显示另一分区旧值，这是参照行为。

snapshot 的 `(partition, relative_file)` 引用贯穿 Drop、清理、同名重建和文件名分配；已掉出当前 manifest 的钉住分区目录也要预检。旧读快照继续持有自身数据和删除状态，不能混用新 GC 状态。维护、索引 sidecar、DropIndex 意图与关闭排空都要遍历所有分区；索引预检还覆盖仅被 snapshot 的 data/delta 钉住、已从当前 manifest 移除的分区，清除未被钉住的后来生成侧车，仍遵守 0010/0011 的提交边界。

B 的分桶写入不能靠提高 manifest.current_seq 预留 ID，那会让 3.x 跳过尚未提交的 WAL。其按桶顺序的 ID/seq 分配、单分区 batch、前缀恢复和确认语义按下述 B 合同单列验收，不由 A 的通过结论替代。

## 互通与回退

使用相同编码不等于自动互通。A 必测 Rust ↔ 真实 3.x、Arrow 15/25，覆盖 WAL、segment、实际合并、多分区删除、转存 delta、旧 snapshot、索引定义和重开。3.x 读取安全的 Rust 目录不会遇到新格式；本设计拒绝的危险 3.x 目录属于上表显式差异。

回退至 0.2.0rc1 时，有非默认分区的 manifest 必须在清理前明确拒绝，受保护文件保持不变，健康 collection 仍可打开。最后一个非默认分区已删、仅剩 `_default` 的目录可能重新处于旧能力范围，应验证正常读回，不能一概声称所有新版本目录永久拒绝。带 key 的 schema 及 rc1–rc3 的 nullable / ARRAY 限制继续按已有规则测试。

### Upsert 与原始行身份

每一行都从**请求写入前的同一全局可读状态**取旧值，再用该行实际提供的字段覆盖；不让前一行尚未写入的合并结果成为后一行的旧值。完成全部合并后才按桶顺序应用。因此同批重复主键的最终胜者由分桶后的 seq 决定，不能简单声明“输入最后一行生效”。缺失 key、显式 None、默认值和更换 key 的差别均按合并后的值路由。

SDK 的普通 Upsert 可能预填 key 为 None / 默认值，partial 可能保留缺失；服务端按真实列集合处理，沿用 0015 对 `partial_update` 的解释。已提供的主键按显式主键处理；只有 schema 开启 auto_id 且实际缺失/解码后为 None 的主键才标记为自动生成。不能依据客户端方法名或最终值是否恰好等于 seq 来猜测这一身份。

同一组输入中的原始行号、字段顺序、valid_data、JSON 检查及动态字段错误随行保留。分桶只增加行位置映射，不能让同名后列、掩码或单行 Upsert 临时批次覆盖原来的坏 JSON 证据。

### B1：生成 auto_id 取行 `_seq`（已采纳）

设引擎进入本次可变状态前的下一个序号为 S，逻辑批共有 N 行。按桶顺序及桶内顺序暂定连续序号 `[S,S+N)`；显式主键行也各占一个 seq，只有自动生成行的主键填为其行 seq。保留原输入索引以构造响应。两个自动生成行不会获得相同 ID；用户显式提供的值不被重新编号。

`key=0,1,0` 的三行按 A1、A2、B 处理：seq 为 1、2、3，原输入位置的生成 ID 返回 `[1,3,2]`；3.x 返回 `[1,2,3]`。这扩展了 0004 原有 ID=seq 决定对**普通成功分桶请求**的影响范围，必须在 B 的发行能力与具名差分中说明。它保护 Rust 新生成的行，不代表旧 3.x 行的 ID/seq 已被修复。

所有加法和生成 ID 的 int64 转换均沿用既有溢出检查，不回绕、不饱和。暂定编号只存在于当前请求局部；不能提前提高 manifest.current_seq、创建预留文件或改变恢复下界。

### B2：确定性失败在首个 WAL 前拒绝（已采纳）

外层 `Db::enter`、collection 查找、Upsert 的范围外参数拒绝、列解码及存储就绪/重试继续沿用实际入口的先后顺序；本节不重新排列这些既有检查。以下 P1 起的“无副作用”均针对**本请求**：处理旧 pending 代或首次懒打开的既有动作不记作本次新行的写入。断言文件完全不变时必须固定这些背景条件。

| 阶段 | 检查及结果 | 允许的本请求副作用 |
| --- | --- | --- |
| P1 业务准备 | 获取既有写许可及状态锁；Upsert 读基础状态并独立合并每行，补默认值，按原输入顺序执行 PK/向量/逐行业务/JSON 检查。空的已解码批按既有语义返回；不绕过外层坏列解码 | 仅请求局部数据；错误不分配编号、不新增行、不追加 WAL |
| P2 分桶与编码 | 计算所有桶及暂定 seq / 自动 ID，按桶顺序完成所有列转换、JSON 规范化和 Arrow/WAL batch 预构造。校验所有桶成功后才能继续 | 同上；后桶 ARRAY 越界也整批无写入。code / reason 沿用对应参照错误，先业务错误、后按桶与列顺序的转换错误 |
| P3 碰撞预检 | 对自动生成的候选 ID 执行 B3；多个碰撞按暂定 seq 递增报告第一个 | 同上；碰撞不能覆盖 P1/P2 中更早的错误 |
| P4 分配与追加 | 一次推进进程内 `next_seq=S+N`，按计划逐桶追加 WAL，每桶追加成功后才应用 MemTable/主键表/位图 | 允许已完成桶前缀；从本阶段开始，已消耗编号在当前进程不回退 |
| P5 完成 | 所有桶均成功应用后，按原索引返回完整 ID 和成功位次；按 A 的触发规则检查自动冻结/Flush | 整批成功；后续维护失败沿用 0007 的已确认写入与重试协议 |

按 0015 保留“列解码/长度/valid_data → PK 与向量/逐行业务 → 原字段位置的 JSON 错误”的既有合同；不同检查所在层的次序以 A 实际入口和已有回归为准。已登记的坏 JSON、默认值、nullable/ARRAY 转换差异不随 B 注销。暂定自动 ID 的计算不得抢先遮蔽既有的业务诊断。

### B3：自动主键碰撞时保护可读旧行（已采纳）

只对 key collection 中**本次自动填入**的候选 ID，查询请求基础状态中的全局最新可读主键，不只查询目标桶，也不按 key/请求分区名缩小集合；该状态须与 Upsert 取旧值、分桶和实际追加属于同一串行写边界。存在时拒绝整批，协议固定为：

- `status.code=1`，`status.error_code=0`。
- `reason="storage error: auto-generated primary key <id> would overwrite an existing row"`，`<id>` 为十进制生成 ID；多个冲突报告暂定 seq 最小者。
- IDs、成功/失败位次及计数字段保持既有错误响应的默认值；不以部分成功响应掩盖错误。
- 不消耗编号，不追加本请求 WAL，不修改旧行；读取能力和同库健康 collection 保持。写入允许的 Released 状态不因碰撞查询新增 load 要求。

该规则按可读旧行判断，不猜测其由 3.x 还是用户显式输入产生。显式主键 Insert/Upsert 的覆盖语义保留；同批用户显式重复也不被改成新的唯一性约束。同一请求兼有显式覆盖和自动生成行时，显式行不豁免自动行的碰撞检查；命中仍整批拒绝。已被全局删除而不可读的旧版本不等于当前可读行，沿用 A 的 tombstone 判定。

只查询本批候选 ID，复用已有按类型主键位置结构，不逐请求扫描全库或添加持久化标记。不提高 seq 跳过冲突、不根据最大主键改写恢复下界、不自动修改旧目录；3.x 自己再次写该目录的风险仍按 0002 登记。

### WAL、故障与确认边界

一条逻辑请求的各桶在同一次数据库写许可和 collection 状态写边界内处理；不通过递归调用公开 Db/RPC 入口逐桶取放锁。正常自动冻结只在整个逻辑批完成后检查，不在桶间按阈值自行切代；追加失败时仍按 0007 冻结/换代并停止本次请求。

一个 WAL 代可含本请求的多个单分区 batch，与其它已完成请求共用同一个 Arrow IPC stream；不为每桶拼接新的带 schema stream。保留同一批内的 `_partition`，删除 `_all` 与每次非空 Delete 一个 seq 的语义不变。

| 失败点 | RPC / 内存 / 重开合同 |
| --- | --- |
| P1–P3 可预期错误 | 本请求整批无行、无编号消耗、无新 WAL；按精确错误返回。其它未确认旧代的处理不能被算作本请求成功 |
| 首桶或后桶 WAL 编码/追加失败 | 整个请求报错；已经完成的桶前缀可见，失败桶不应用 MemTable。原 writer 作废，不补写、不 finish、不续写；保留完整前缀，停止后续桶，沿用冻结/同步/重试协议 |
| 完整桶边界或半截尾部后进程退出 | 重开只接受已校验的完整 batch 前缀；数据、编号、Delete 和全局可见性与实际保留前缀一致，后续自动编号受 B3 保护。不把报错或未返回请求的全部行当作已确认 |
| 锁内 panic / 发布无法证明一致 | 沿用状态毒化、保留 WAL、拒绝后续不安全操作及重开恢复；不错误回滚已提交 manifest 或返回成功 |
| 全部桶成功后的自动 Flush/维护失败 | 按 A/0007 记录待重试状态并保留已确认写入；不改变既有提交点前后责任或 fsync 保证 |

实际恢复以完整 batch 校验结果为准：WAL 已完整写出但 MemTable 尚未应用时退出，该 batch 仍可能被恢复；不能仅凭 RPC 未返回或报错推断尾桶一定没有可回放数据。半截或无效尾部仍停在已校验前缀。

真实 I/O 故障后会有未确认前缀；B2 的全部预构造不构成跨桶 I/O 事务。重开仍取 0007 的已提交/可恢复序号下界继续，不要求记住未落盘的进程内预留范围；生成 ID=seq 与 B3 共同避免覆盖可读旧行。此前已成功返回的数据在故障、Flush、合并及重开后必须保留。

### 存量目录、物化与互通

1. 先读 schema，在内存里把精确的 16 桶加入逻辑候选注册集，再执行路径/pins 预检、WAL 标签检查及恢复。即使磁盘 manifest 不存在或尚未列出桶，合法 `_pk_0`…`_pk_15` WAL 仍可恢复；保留 manifest 中其它合法分区。禁止仅按 `_pk_` 前缀放行，`_pk_16` 等未知名称仍拒绝。
2. 逻辑补桶和读取不创建目录、不重写旧 schema/manifest、不推进任何 seq。它不授权跳过 A 的既有恢复/孤儿清理责任；危险名称、别名、链接及不可信引用必须在回放应用/清理之前拒绝。故障 collection 不影响同库健康 collection。
3. 新建 collection 在既有 staging 创建 schema 与完整逻辑注册集后原子发布；首次物化桶目录后，在任何数据文件写入或 manifest 提交之前复核完整候选及 pins。不能因继承文件已经同步而省略复检；准备失败只安全回收本次自建的空目录，不递归删除复用或钉住内容。
4. 继续使用 manifest format 2、3.x schema JSON 的 key 字段、既有 `_partition` WAL 和 Parquet 路径；不增加行归属列、请求提交标记、私有路由格式或预留水位。一次多输出 Flush、单分区合并、全局删除、GC、snapshot、sidecar 和索引意图沿用 A。
5. 必测 Rust↔3.x、Arrow 15/25 的 WAL-only、segment、混合、合并及坏自动 ID 前缀；Rust 写出的合法目录由 3.x 读回并继续写入。导入 3.x 已违约目录时，只承诺 B3 对本实现的生成写入保护，不声称原目录已修复或随后由 3.x 写入也安全。
6. `0.2.0rc1` 及 0.1 rc1–rc3 对 key schema/目录必须在残留清理前明确拒绝，受保护文件不变；同库健康 collection 可读。非 key 目录仍按既有能力开放，不因版本字符串一概拒绝。

### 读取、并发、性能与范围保持

count/Get/Query/Search、query iterator、range/search iterator V1 的选择集、PK 顺序、重复主键、过滤三路线、null、范围窗口和距离误差预算全部继承 A/0015/0016。不按 key 推断额外的隐式分区选择来改变结果；空 count(*) 及未知选择、load 状态、表达式错误仍按既有分派。

继续使用现有写入许可、状态锁、flush 锁、compute 约束及不可变快照，不增锁层级、不移动磁盘提交到状态锁内。准备批次与源位置映射的寿命覆盖全部追加；读取已发布快照不看到桶间中间状态。受控并发测试必须固定写者、Delete、Flush/合并、旧快照及 close 的交错，不能以 sleep 证明串行性。

非 key 快路径不计算 MD5、不枚举 16 桶、不执行新增碰撞保护。key 预构造必须有有界的请求缓冲，不复制全库主键或向量；实测峰值内存、编码/写入和恢复成本。默认路径与同机 A / 已发布 rc1 对照；性能声明同时按 0001/规则 7 使用 3.x 和 2.5.1 中能力等价的基线，不能用拒绝或忽略 key 的实现当作 key 基准。保留三轮顺序轮换、相同输入/参数/线程设置及逐批正确性核对，覆盖普通/JSON/ARRAY、单桶/多桶、Upsert、S1、批检索与恢复 RSS。历史 N7 性能不充当 B 实测。
