## 实现与产物

新增标量字段的 nullable/default_value，沿用 3.x schema/Arrow/Parquet 编码，无新依赖或磁盘格式。输入保留缺列、显式 null 与有效值；默认值在 core 填充，普通/partial Upsert 按参照分别处理。向量 nullable、向量默认值和 ARRAY 仍在本切片外。

ColumnData 只在实际有 null 时用 Nullable 变体封装稠密值列和按位有效性，全部有效仍是旧变体。快照、gather、相邻块合并、WAL/segment 转换与 compaction 同时携带值和空值位。空值位与删除位区分，不通过零值、空字符串或 JSON 文本猜测空值。字段定义 nullable 但全部有效时不持有列空值位图。

三条整表达式路线、S1 旧快路径及已登记 INVERTED 扫描差异保留；Query/count/Get/Search/Delete 输出与 valid_data 对齐。gRPC 接受标量紧凑/完整布局。负责人评审指出首轮 JSON 语法校验早于主键等业务检查；修复后 JSON 内容由引擎按行、按字段校验，仍检查被同名后列覆盖的坏值，协议长度与 valid_data 检查保持在先。JSON 默认值沿用 0004 的顶层标量/字符串差异，不静默改为参照的错误存储行为。

## 复核与修复

按 [code-review-rules](../../.agents/skills/code-review-rules/SKILL.md) 作本地自查，合同是 A 的不变量及现有 0003/0005/0007/0010 失败协议。搜索模式包括 `InputValues::|ColumnData::|valid_data|nullable|default_value`，范围为 core/grpc 的生产者、存储、读取和响应；再检查 `append|convert|push_row|append_column|decode|encode` 的替代出口。主键与向量的直接匹配由 schema 不变量保证，不为未来假设调用者扩展能力。

本轮发现并已修复的同类出口：

- nullable 包裹后，MemTable 的类型匹配仍按外层变体拒绝：统一检查内部稠密类型、nullable、掩码长度及无嵌套，避免 WAL 追加后的内存发布失败。
- schema 默认值描述误用请求参数的整数饱和：改用默认值专用严格转换；INT32/64 越界明确报错，Unicode 十进制、4300 位字符串限制及整数转 float 溢出与参照核验。auto_id 对空主键的赋值优先于未使用的错误默认值。
- 同名后列覆盖可能隐藏前列的畸形 JSON：首轮在协议解码时校验；此处提前报错被负责人评审确认为阻断。修复后保留原始列引用，在引擎轮到该行、该字段时检查被覆盖的 JSON；合法的同名列仍由后列覆盖，失败请求没有新增行。
- 回退工具初稿边建多集合边合并，后续 create 按 0010 可取消尚未提交的维护：改为稳定目录后独立重开加载，再关闭排空，仍要求真实合并文件。未改维护协议、未放宽断言，原失败输出保留。

当前请求的确定性失败清单：协议类型/槽位、长度/掩码、schema 限制、字段缺失/None、默认值与标量类型、VARCHAR 长度、JSON 解析/有限值和 Arrow 精度转换，均在当前请求第一次 WAL 追加和序号状态变更前完成。既有目录重开清理、已接受维护和待提交代重试仍按 0007 执行，不由“当前请求失败”推导整个服务绝无既有存储副作用。

新增失败 Delete 用例先保留文件和行集，Query/count/Search/Delete 均逐字对照参照错误；之后比较文件与行集，再用下一次成功写入和 flush 的 current_seq 证明没有消耗序号。反证与变异结果单独保留，不借失败后单跑通过撤销失败。

另以仓库外源码副本和互相独立的 CARGO_TARGET_DIR 做两项变异：输入 is_null 始终 false、存储 is_null 始终 false。两者均由新增业务状态测试拒绝，分别出现 3 项和 2 项失败；确认是断言失败，不是编译/环境失败。工作区与开发 wheel 没有被变异改写。
