## 调度与耗时诊断

用户反馈候选耗时后，独立远端 x86_64 与本地 Linux arm64 改为并行；每个平台内部仍按原顺序执行。ARM 总控结束后遇到远端独占候选目录检查时停止，由 x86 独立总控接续；统一门槛分别检查两端完整步骤和冻结身份，未重复执行已通过阶段。x86 差分只增加 pytest 耗时及 JUnit 记录，收集范围、用例和断言保持不变。仓库外 5 项 cProfile 诊断单独保存，不计作候选矩阵替代结果。

远端工具镜像继承 `/bin/bash` entrypoint，首次控制容器在产品启动前退出；保留初始日志和容器，另建显式 sleep entrypoint 的控制容器；工具解释器又因历史 `/prior` 挂载缺失而在启动前拒绝，随后按旧工具依赖补齐 `/prior` 和 `/revision` 挂载并完整预检，不修改旧文件或软链。预检的版本字符串曾因外部编排的 shell 引号丢失报 SyntaxError，改用逐参数 Python 调用后重验，全部发生于候选源码准备之前。PID 1 编排入口另显式指定 Python 与 Docker socket 所需用户；被测产品容器保持冻结探针定义。

远端执行期间 SSH 报 Broken pipe（本地返回 255），Docker 内原矩阵进程仍在运行；固定原 exec ID 重新观察；完成时 exec inspect 记录 126，但 Docker 的同一 exec ID / container ID 对应唯一 exec_die 原始事件明确为退出 0，63 阶段及最终结果标记也全部成功。原事件、inspect 不一致与调查日志均保留，具体 Docker 内部原因尚未确认；统一门槛严格要求同一进程的退出事件为 0，并检查全部真实阶段返回码和平台日志。不得把 inspect 的 126 改写成 0。不重启、不重复远端矩阵；网络中断日志和重接证据一并保留。
