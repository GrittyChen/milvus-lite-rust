## 失败与根因

1. **`35fe797` 快速层 rust-fi（ubuntu-24.04-arm）**：partition key 崩溃边界用例中，WAL 暂停的恢复信号发送端在 `if` 块内被提前 drop；暂停在写入后立即断连并 panic，与监视线程的 `exit(88)` 竞争，结果随调度而变。修复 `68c8887` 让发送端存活到子进程结束。
2. **`68c8887` 对照层 diff-3.0.2（ubuntu-24.04-arm）**：`test_drop_displaced` 在 flush 后立即外部移走集合目录；3.x 的后台索引写入晚于移走时逐级建目录、重建原路径，同名 create 报目录已存在。修复 `ed63234` 先正常关闭重开（等后台写完）再改目录，并在 [0006](../decisions/0006-m2-scope.md) 的 3.x 缺陷栏补记该行为。
3. **`ed63234` 对照层 diff-3.0.2（macos-15）**：`test_partitions` 的合并场景在分区第四个文件触发合并后立即写入第五个文件，再逐序比较 query 结果。3.x 的后台合并整轮持 `maintenance_lock`、与 flush 串行；本实现准备期不持 flush 锁，提交时追加到当时 manifest 尾部，交错时来源顺序不同，这是 [0010](../decisions/0010-compaction-and-tombstone-gc.md) 已登记的差异。修复 `04a5005` 在第四个文件后正常关闭排空、核对两边都已合并，再写入。复现方式为在合并准备后临时加 3 秒延迟；带延迟的全量差分 421 项四分片通过，未发现其他同类用例；移除延迟后从干净源码重建，全量差分通过。

三项都先确定性复现、再修复，经独立评审后在负责人确认下单独提交到试点分支。

## 分支保护

负责人决定 `main` 同时要求 `ci-pass` 与 `compare-pass`：对照层在试点中实际发现过差分失败，只要求快速层会让差分失败的提交进入 `main`；对照层已在每次工作分支推送时运行，不增加额外成本。负责人设置并回读的保护规则：

- 必须通过的检查：`ci-pass`、`compare-pass`，来源限定 GitHub Actions（App ID 15368）；
- 管理员不能绕过（`enforce_admins`），不使用管理员 bypass；
- 禁止强推与删除，要求线性历史。

推送方式：在工作分支推送并等两项检查通过后，把同一提交快进推送到 `main`。对照层不在 `main` 上由推送触发，`main` 上的检查结果来自工作分支对同一 SHA 的运行。

实测：

- **快进**：`c0cc6f6` 在 `ci/pilot` 上两项检查通过后，从 `1688547` 快进推送到 `main` 成功，推送输出没有规则绕过提示；`main` 上由推送触发的快速层运行 39793398896 成功。
- **失败推送被拒**：`54bf8ea` 的 `ci-pass` 为 failure 后，推送到 `main` 被拒绝：`GH006: Protected branch update failed for refs/heads/main`，`2 of 2 required status checks have not succeeded: 1 failing`；`main` 保持 `c0cc6f6`。
