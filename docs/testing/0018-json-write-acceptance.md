## 实现及信任边界

产品仅修改 [collection](../../crates/core/src/collection.rs)、[key 写入](../../crates/core/src/collection/partition_key.rs)、[runtime](../../crates/core/src/storage/runtime.rs) 与 [Arrow 转换](../../crates/core/src/storage/arrow_data.rs) 四个文件。

`normalize_data_json` 完成既有解析、有限浮点检查与首轮规范化之后，返回私有 `NormalizedColumns`。该类型持有 schema 和列的只读借用，字段私有，不能在构造后修改原列或 schema；其 `wal_batch` 只复制已规范化的 UTF-8 文本到 Arrow。唯一构造入口仍执行原规范化，不能由任意类型标签或外部布尔参数声明文本可信。

普通 Insert / Upsert 使用 runtime 的私有追加入口；key 的每个桶在原预构造阶段编码。写入检查、序号分配、全桶准备、WAL、MemTable 与读视图的先后顺序保持。公开 `data_batch` / `wal_data_batch` 及 runtime 通用追加仍保留完整规范化，恢复、Flush、compaction 与 `$meta` 的处理不改。无新依赖、格式、锁或 Python 业务逻辑。

正式构建不含 JSON 编码计数；计数仅为 Rust `cfg(test)` 的线程局部接缝。测试确认普通 / key 的 Insert / Upsert、nullable 及 JSON 默认值都只规范化一次；恢复重复编码的变体会触发计数断言，绕过首轮规范化的变体会触发非法输入拒绝断言。

## 准备失败及证据边界

- 初次 Rust 编译的切片重借用错误、默认值测试的 trait 调用错误已修正，保留原编译日志；后续完整阶段重新编译通过。
- 新增 WAL 差分的首个准备版本漏掉子进程内的 `Path` 导入。随后发现空动态字段的物理编码在原正式 Rust / 3.x 上分别为 `{}` / null；优化前原样复现相同差异。测试改用两端相同的显式非空动态字段，保留精确断言，不修改这条既有编码路径。
- 共享 Cargo target 首次将前一变异的产物误用于后一变异。该次通过不算反证证据；强制更新隔离源码时间并以 verbose 编译日志核验实际 manifest 路径，重建后的变体被指定拒绝断言拦住。主树随后也强制重建并通过完整回归。
- Linux arm64 的首轮 FI 在只读源码挂载下无法创建相对路径测试临时目录。保留失败，改为核验同一源码归档后在仓库外可写副本运行；完整 workspace / FI / Clippy 均重新执行通过，未禁用测试。
- SDK 环境初次引用了旧环境中不存在的 Python 子目录，实际版本核验发现未切到 2.6；已在新环境离线安装 2.6.17 并重新核验，旧环境未修改。SDK 测量入口首次将返回的 protobuf ID 容器直接交给 JSON 编码器，自检 / 冒烟后改为保留类型的列表展开，重新完成完整工具自检及新路径冒烟。
- 源码归档的首个准备版本以发布冻结树为底，遗漏了之后已提交的文档；产品 127 项一致，但该归档不作为完整工作树身份。有效版本改用当前 HEAD 加全部待审文件，逐项核对完整源树，旧准备记录保留。

Linux 本轮只扩充 Rust 组件 / 故障与完整 FI 编译面证据，不替代两条 SDK 在目标平台上的最终候选矩阵。Intel Mac、最低系统真机、真实断电与真实重启均不新增实测；边界沿用 0013。本记录的已完成阶段均有本轮实跑与身份记录，不从历史矩阵推定通过。

## JSON 写入资源：保持独立归因

24 次固定分进程探针均通过，仍为原始请求、各六批 Insert / Upsert、17 个快照，未改采样或状态 / 内容断言。普通模式在 Upsert 完整读回后的服务端峰值，优化前 / 后中位数约为 519.9 / 518.6 MiB；key 多桶约为 476.9 / 475.1 MiB，范围重叠。3.x 同阶段约为 447.5 / 427.2 MiB。
