## 结论

0.4.0rc1 交付 `0.3.0rc3` 之后合入的 0023–0026（集合管理与多数据库、分组检索、TIMESTAMPTZ 与 `timezone`、HybridSearch 与 rerank），是发行工作流第一次在这些产品代码上运行。冻结提交满足候选方案的四项冻结条件；前置 CI 与 Compare、第二次演练和正式运行都在 attempt 1 一次全部成功，计数逐项与收集数一致，没有失败、忽略或意外跳过。第一次演练只有签发步骤因 Sigstore 透明日志的外部故障失败，经负责人认定为外部基础设施故障后，在透明日志恢复后另开一次演练（见「演练」）。正式运行在签发前完成本地保全，以保全工具输出的审批行批准后，一次签发覆盖七个附件的来源证明；签发后补存与复核通过，回执不变。`main` 已普通快进到冻结提交，台账登记 `candidate` 并合入，发布准备工具核对通过。

停服路径段错误由负责人对本版谱系**再次做发布级风险接受**：根因仍未查明，没有新的定向证据，不是修复，也不是继承（见下文）。本记录不声明生产可用。

## 停服段错误：再次做发布级风险接受

[停服段错误调查](shutdown-segfault-investigation.md#结果与出口)的继承条款只针对首个真实候选，且要求差异不涉及停服与服务生命周期；本版相对 `0.3.0rc3` 改动了最终 flush 的下游与服务的打开路径，因此不继承。负责人于 2026-11-07 依据[候选方案](../releases/0.4.0rc1-candidate-plan.md#停服段错误再次做发布级风险接受)的只读核对，对本版谱系再次做发布级风险接受；适用范围以 D 的 `crates/` 树与 `Cargo.lock`（相对 D 只差三个本项目 crate 的版本）、Rust 1.98.1 与 CI 固定的 grpcio 1.84.0 为准。上节四项冻结条件在 C1 上全部成立。

这是「根因未查明、再次显式风险接受」，不是修复。截至候选验收的九次运行（冻结分支的 CI 与 Compare、两次演练、正式运行、`main` 上的两次 CI、台账分支的 CI 与 Compare）中，三次发行工作流运行各自的 28 个「崩溃现场」步骤全部为 skipped；九次运行的完整日志中没有 SIGSEGV、Segmentation fault、signal 11 或 core dumped 字样。本版已作为不可变预发布发布；今后任一运行再次出现停服路径 SIGSEGV，即撤回这一风险接受，停止对本版的后续使用与推广，按 [0013](../decisions/0013-first-release-platform-and-packaging.md) 的发布后失败处置在 Release 说明中标明该版本不可用，并按调查记录的停止条件处理；台账保持 `released`，不替换 tag 或附件。
