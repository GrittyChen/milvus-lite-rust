## 停服段错误：再次做发布级风险接受

依据、理由、残余风险与适用范围见[候选方案](../releases/0.9.0rc1-candidate-plan.md#停服段错误再次做发布级风险接受)，冻结条件第 4 项在 C 上成立。本次不是「停服路径未变」的继承：停服函数体与顺序都没有改动，但建图线程的任务新增 `attach_file`，AVX2 分派新增两个按段打分函数，触及「服务生命周期中的线程」与「原生交界」，按调查记录「失效与继承」须再次接受。

接受的残余风险：`0.8.0rc1` 接受的全部残余风险；建图线程在停服窗口内执行 `attach_file` 时的取消与 join 没有定向停服压力证据；新增的 AVX2 按段打分函数与本版的过滤代码不在任何一次 ASan 运行的覆盖内（ASan 复跑没有执行）。

**适用范围**：谱系以 D 的 `crates/` 树 `f2c94889…` 与 `Cargo.lock`（相对 D 只差三个本项目 crate 的版本）为准，Rust 1.98.1，同进程 grpcio 为 CI 固定的 1.84.0；dump 进程另有 `dump30.txt` / `dump26.txt` 固定的 BulkWriter 依赖。下一个候选以此为基准比较。

**运行核对**：自 `0.8.0rc1` 正式运行之后至 D 的运行见[候选方案](../releases/0.9.0rc1-candidate-plan.md#停服段错误再次做发布级风险接受)第 5 项。本候选的运行与日志检索见「日志检索」。

这是「根因未查明、再次显式风险接受」，不是修复，也不是继承。今后任一运行再次出现停服路径 SIGSEGV，即撤回这一风险接受，按调查记录的停止条件处理，不重跑掩盖。

## 负责人确认

2026-11-27 负责人在方案评审时确认：

1. **停服段错误：再次做发布级风险接受**，对象与适用范围见上节。
2. **重新计数：累计口径**，不另触发，映射见「重新计数」。理由：这些提交不改并发模型、锁序与持久化，过滤与大 limit 的正确性由差分、随机对拍与变异检查覆盖。这是 0020 第 2 条「经评审约定」的替代，不写成已完成稳定性计数。
3. **不执行演练**：签发路径相对 `0.8.0rc1` 未变，按 0039 决策 A 正式运行不引用演练，结果见「签发路径与不引用演练」。
4. **降级不做本地检查**：持久化格式不变；`0.8.0rc1` 读取本版目录由正式运行的 previous-reader 核验（7 个场景通过）。
5. **老内核抽查不执行**：本版没有新增系统调用、文件写入方式或 `server` 子命令的改动；关于老内核只引用 [0013](../decisions/0013-first-release-platform-and-packaging.md#候选阶段决策) 决策 1 的历史证据。
6. **ASan 复跑不作为门槛**：没有执行，缺口写入上节的残余风险。
7. **在本机执行**：本地证据留存于发行所在机器；组装脚本沿用 `0.5.0rc1` 起的版本（SHA256 `32ee18ec…`，内容不变）。

以上七项由负责人在方案评审时作出，不代替对本记录的确认；本记录未经负责人逐项单独确认。负责人授权按方案连续执行至发布结束，只在产品级错误时停下；签发审批经负责人 2026-11-28 明确授权后由执行者以负责人本人在本机的 `gh` 认证完成（见「保全、审批与签发」）。执行者作出的判断：触发前与批准前只读核对的口径，以及「日志检索」的范围。

版本已消费。负责人审阅本记录后如不同意：在发布前按[候选方案「执行检查点」](../releases/0.9.0rc1-candidate-plan.md#执行检查点)的规定放弃，台账登记 `abandoned` 并换用新版本号；在发布后对第 1 项按「停服段错误」一节撤回接受，处置同 [`0.7.0rc1` 记录](0.7.0rc1-acceptance.md#停服段错误再次做发布级风险接受)：在 Release 说明中标明该版本不可用，台账保持 `released`，不替换 tag 或附件。
