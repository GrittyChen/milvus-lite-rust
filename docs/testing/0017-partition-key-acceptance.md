## 实现边界

- schema / Describe / schema.json 接入 `is_partition_key`；仅支持一个非主键 INT64 / VARCHAR key，校验顺序保留基本 schema 错误在前。MD5 路由使用无传递依赖、无构建脚本的纯 Rust `md5` 0.8.1（Apache-2.0 / MIT）；已核对完整依赖树，未引入 C++、CMake、protoc 或新系统库。
- key 的 Insert / Upsert 独立进入请求准备路径。Upsert 每行从请求前全局可读状态合并，保留原始 JSON 检查与行号；按桶首次出现顺序预构造全部列和 WAL Arrow batch，再做自动 ID 碰撞保护，一次推进 seq，逐桶追加成功后发布。自动冻结仍只在整个逻辑请求尾部检查。
- 非 key A 的 `pending`、写入与错误优先级保持；内存 Collection 复用既有分区可见性组件，附加持久化状态及重开时释放内存模式状态，不持有两套写入状态。
- 新建在 staging 内准备完整逻辑注册集；存量读取只在内存中补精确 16 桶，保留其它合法分区，在路径 / pins / 实际回放的 WAL 标签检查之前完成。打开不为补桶创建目录或重写 manifest。过期 WAL 的序号保护沿用 A / 0007，不能把它误写成放宽待回放未知桶。
- Flush 物化目录后无条件复检完整命名空间和 pins；失败仅尝试回收本次自建空目录，不递归删除复用目录或钉住文件。manifest format 2、schema JSON、Arrow WAL / Parquet 形状不变。
- 沿用 A 的写许可、状态锁、flush 锁、不可变快照、提交 / 恢复 / 合并协议，不新增锁层级或磁盘格式。

三项已采纳差异由具名差分分别验证，普通差分不放宽：B1 生成 ID 取分桶后的行 seq，例 `[1,3,2]`；B2 后桶的确定性错误整批不写入、不耗编号；B3 自动 ID 将覆盖请求前可读旧行时，整批 code 1、error_code 0，原文为 `storage error: auto-generated primary key <id> would overwrite an existing row`。显式覆盖仍允许，真实 I/O 仍是已校验前缀保证。

## 实施期间发现并修正的边界

1. 重开后必须清除仅供非持久化入口使用的 key 可见性状态，否则追加会访问错误 source。已加连续三次重开追加回归；持久化实例只使用恢复出的那一套状态。
2. 存量 schema 的 key 默认值可能是超出 i64 的整数。直接 raw Insert 应在字段业务检查处报 code 6，不能在路由阶段变成内部存储错误。key 的范围判断及整数错误文本单独处理，覆盖正负 i64 外及正负 128 位整数，保留 PK / 向量优先级；失败不写 WAL、不耗编号。非 key 的既有校验和错误诊断不在本片改动。

SDK 会拒绝同批逐行缺少 typed 列的部分组合；不能把该客户端拒绝当作服务端分桶成功。动态字段逐行不同键集是真实 SDK 请求，直接引擎的遗漏 typed key 则另按固定真值与组件用例验证。

## 单独登记的既有问题

非 key 集合的同批重复 PK partial Upsert 会累计前一行的动态字段更新：初始 `{id:1,x:0,y:0}`，请求 `[{id:1,x:1},{id:1,y:2}]`，A 与已发布 0.2.0rc1 在 active / segment 都得到 `x=1,y=2`，参照为 `x=0,y=2`。本轮用独立 A / 已发布环境重现；该问题早于 B，另行处理。B 按请求前状态合并，真实 SDK 回归与对应变异验证此边界。

此前 JSON 写入相对 3.x 的差距也仍是已登记的独立事项；本片不能因为扩展 key 支持而宣称已经解决。新旧性能按实际构建、操作和规模分别比较。
