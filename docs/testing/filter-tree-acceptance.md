# 0014 切片 B 过滤表达式验收

日期：2026-10-15。实现基线为 `c69905a`，S1 性能基线按冻结合同使用切片 A 的 `a10477f`。参照为 milvus-lite 3.2.1 / `43d1257`。

## 实现与范围

单次解析保留原 arena、位置和语法诊断，补全布尔、路径和函数的节点内容。`tree` 绑定 schema 并为整条表达式选择路线，`columns` 执行扩展树的列式规则，`dynamic` 保留整源类型推断，`python` 与平面的 `python_json` 共用逐行值规则。已有 S1 字段/字面量、and 和顶层主键 in 保留原快路径；没有新依赖、持久化文件或协议字段。

支持范围与两项确认保留的参照缺陷见 [0014](../decisions/0014-index-definitions-and-filter-expressions.md#切片-b过滤表达式)。未知 contains 目标按 None，保留字段目标 `_seq` 读取实际保存的 seqs，查询排序用的 orders 不参与该语义；普通保留字段表达式仍拒绝。语义检查与静态路由不被运行期短路绕过；执行期短路只属于 Python 路线。

Arrow / hybrid 的 in 对缺失值与 Python 不同：Arrow 的 is_in 求 False，取反可能匹配；Python 求 Unknown，取反仍不匹配。NULL 类型上的 LIKE、两个 NULL 类型列的比较没有 Arrow 内核，会触发 hybrid 整树回退；不能用一个 Unknown 掩码代替回退。这些组合由真实组件语料固定。

求值只生成当前不可变快照的局部掩码，后一源失败不发布部分结果。Delete 在全部求值成功后才进入既有 WAL-first 写入路径；本次求值失败不分配序号、不改 WAL、manifest 或行集。load/deleted、解析、存储重试与分页的原入口不变。Scalar INVERTED 仍按扫描，已登记的索引计划差异扩展到新增形式。

## 组件、生命周期与反证

- 原 7,791 条语法语料与原动态语料保留；新增 4,737 条组件语料，保存输入、路线、掩码或错误阶段/类型/原文。覆盖全部当前标量类型、JSON/动态路径、三值组合、成员转换、字段比较、LIKE 两种转义/结束语义、容器相等/次序、非有限 JSON 常量、孤立代理项、重复键、整数数字长度限制与解码深度边界。
- Arrow 15.0.0 与 25.0.1 各严格 verify。float→int64 的截断诊断同时保存两版实际原文（1.1 与 1.100000），Rust 对齐固定的 Arrow 25；其他阶段、路线、结果和错误不放宽。
- 核对单源多块与跨源绑定、active / frozen / committed / 重开、覆盖后的实际序号及旧快照、后一源出错时 Query/count/Search/Delete 的原子边界。失败删除前后逐字节比较文件及完整行集，再通过下一次 insert/flush 的 current_seq 证明未消费序号。
- 10,000 项布尔链验证解析、绑定、求值和析构不依赖宿主调用栈；9,997/9,998 层 JSON 字符串按固定参照边界分别成功/RecursionError，未访问分支不解码。深层 JSON 节点平面保存，不改变存储读取的既有 JSON 校验。
- 四个隔离变异均被新组件语料拦住：Unknown 提前清为 False、只把失败比较叶子回退 Python而不重算整树、整数溢出改成可回退、取消 Python 短路。使用仓库外源码和 target；每个变异前强制重编译 core，源码、日志及失败记录分别保留。
- 恢复 8 个参照 adapter 函数、参数化 23 条，AST 核对用例本体与 `43d1257` 相同。nullable、分区、ARRAY、算术等仍有其他阻断的用例继续列范围外。
- 继承 0006 已确认的 2^63 转 int64 安全边界，新增 schema in/not in 与浮点列转换的失败删除测试。arm64 / Arrow 25 的双向 is_in 探针错误命中已核实；本实现不把 float(2^63) 饱和为 INT64_MAX，其他情况不放宽为架构例外。

## 评审后修复

- Python 容器有序比较保留可比较、数值无序与 TypeError 三类结果。首个不相等的元素对在任意嵌套层发生 NaN 数值无序时，四个有序比较为 False，外层 not 可以匹配；TypeError 仍为 Unknown。相等 / 容器身份规则跳过的 NaN 不触发这一分支；顶层数值、短路、解码规则及 Arrow / hybrid 内核保持原行为。
- exists 的 FLOAT / DOUBLE 诊断分别使用 `float` / `double`；补全当前字段类型的真值。普通标量过滤引用向量字段时改为参照的 code 6、完整类型诊断与源码位置；整字段 exists 的优先级与 contains 目标参数的已确认例外保持不变。
- 扩充字符串组的直接 / 取反四种有序比较、嵌套列表、解码值对动态值、NaN / Inf / None / 不兼容类型及重复键对象。修复前在真实 Arrow 15 / 25 生成的新语料中出现 228 项差异；旧 wheel 的真实 RPC 在 NaN 容器取反场景也失败。
- 在仓库外副本中分别撤回 NaN 比较、exists 类型名和向量诊断修复，强制重新编译 core，新语料分别出现 28、50、150 项差异。原四项反证也重新执行并全部拦住。
- 对象按原键序保存条目，以哈希索引处理重复键、路径访问与相等判断；索引属于平面解码文档，不增加依赖或持久化格式。大对象回归同时覆盖反向键序、末值覆盖、孤立代理项、缺键、无效原文及解码值对普通动态对象。
- 清扫模式为 filter 下的 `partial_cmp|number_cmp|ordered|is_nan`、`name\(\)|to_ascii_lowercase|unsupported`、`Object|keys|key|iter_mut|find`；核对 Query/count/Search/Delete → `filtered_chunks_compiled` → 三路线及 Delete 求值成功后才写 WAL 的边界。新修复没有新增 I/O、修改锁序或改变持久化时序。

纯 schema 的新形式仍先收集整源活行引用并物化引用列，存在额外遍历与列复制开销。已有 S1 快路径不走这条通路；本轮不重写该结构，也不对新形式或其与 S1 的性能差距作保证。

## 对象规模探针
