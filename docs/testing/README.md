# 证据的存放与复核范围

本目录的验收与调查记录引用三类证据，三者并列，区别在于谁能复核：

| 类别 | 内容 | 谁能复核 |
| --- | --- | --- |
| 仓库内可重跑 | 测试、调查与基准工具，固定真值及其 `--verify`，记录中的命令与通过判据 | 任何人拉取仓库，按记录准备参照实现与环境后重跑；记录基于的提交只有已推送的才能核对 |
| 公开产物 | GitHub Release 的附件与 `SHA256SUMS`、tag 及其冻结提交 | 任何人下载后核对哈希 |
| 本地留存 | 原始日志、环境、数据目录、未发布的构建产物（开发、候选与 FI wheel）及证据包，存放在负责人自有、未公开的存储中（含本机与远端验收主机） | 只有留存者；不随仓库分发 |

判断是否属于本地留存，看证据是否入库或公开，不看措辞：记录中保存、保留、留在、另存或归档于「仓库外」，「仓库外证据索引 / 证据包」，以及「外部 / 开发工作目录」，都指本地留存。仓库外的诊断程序、探针、原型与插件没有入库，依赖它们的结论只由本地证据支撑。随附的证据包哈希、清单项数与运行身份只用于与本地存档逐项比对。同一产物的类别可随发布改变：候选阶段的 wheel 与 sdist 属于本地留存，以相同字节公开发布后属于公开产物。第三方只能借前两类重跑或核对；历史运行的原始结果本身，第三方无法复核。

「在仓库外的新目录运行」「仓库外安装」「仓库外副本」「输出放在仓库外」一类说法描述执行方式，与证据存放无关。

## 写法约定

新记录写三类内容：结论；仓库内可重跑的方法（工具、真值、命令与通过判据）；公开产物的身份（提交号、Release 附件哈希）。

本地留存的证据写作「由负责人本地留存」，不写位置：不写「位于 / 保存在某目录」，也不写工作目录名、卷名、主机名或路径（另见 [AGENTS.md](../../AGENTS.md) 规则 14）。运行身份与哈希可以作为标签记录，即使运行身份与目录同名。若某项结论只能由本地证据支撑、无法用仓库或公开产物重现，须在记录中写明。

既有记录不回溯迁移，按上文的分类阅读。修改某份记录中涉及证据存放的表述时，同一记录内写出存放位置或会被误读类别的表述一并按本约定改写，去掉位置的同时写明类别；只写「保留」「保存」而无位置的表述按上文分类即为本地留存，可不改。
