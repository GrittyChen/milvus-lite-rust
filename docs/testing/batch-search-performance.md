# 批量检索性能专项

日期：2026-10-09。第一轮的 Rust 对照为 `e23acd5`，第二轮为 `cff6db7`；两轮参照均为 v3.2.1 / `43d1257`。性能目标及精度约束沿用 0001 / 0004，两轮均保持 0005 的计算池、任务提交、锁、候选内存上限、停服及公平性设计。

## 定位与最小改动

对独立服务连续发出百万行、128 维、nq100、FLAT L2 请求，macOS sample 的计算线程栈主要落在 `flat::diff_sq_lanes_batch` / `score_batch`，TopK.push 次之。采样期间请求明显变慢，采样耗时不进入正式表；等待栈不能直接解释为调度开销，未据此宣称调度是瓶颈。

单线程的隔离距离核探针，百万候选、4 查询、128 维，初步三次预热后值约 40–44 ms；展开内层循环约 36–37 ms。checksum 相同只作诊断，不替代逐位/差分验证，也不能将微测比例当作 RPC 收益。真实 RPC 冒烟差异较小，进一步配对计时后才能决定收益。

第一轮保留两项局部改动：

- 显式展开批量距离核的 4 条查询，把同一候选元素供四个独立累加器使用；每条查询每一路仍按相同 k 顺序累加。保留 16 路、同一归约树、尾部顺序、COSINE 换算和 NaN 处理。L2 仍逐元素相减再平方，没有 FMA、范数展开、unsafe 或额外依赖。
- 强制内联原 TopK.push，减少每个候选的调用开销；不改变 bound、筛选阈值、排序键、吸收或结果顺序。

组大小仍为 4，BLOCK_ELEMS、row_blocks、groups_per_wave 与 Compute::for_each 均未改；同时存活候选不因 nq 增长，读快照和磁盘协议不变。新回归用原嵌套循环对照新距离核，覆盖三度量、维度边界、32768 维、NaN、±inf、±0、有限大数与尾部，逐位核对四条结果。既有串行/并行、并列、稀疏存活行与生命周期用例继续作为门槛。

## 第二轮：按分数拒绝后再读取候选位次

### 定位与实现边界

对第一轮冻结产物重新采样，活跃计算栈仍以批量距离核、scan 与 score_batch 为主；候选分配及末尾筛选占比较小。另在仓库外的纯内存原型中，按叶子任务测量扫描与末尾筛选，并在调用线程测量分波、合并与结果读取。百万行、128 维、nq100 的完整原型中，合并约 2.6–4.0 ms，结果读取约 0.3 ms。这里的累计叶子耗时是各任务的墙钟耗时之和，包含抢占，不能当作 CPU 时间；原型输入使用独立生成器，不进入正式性能表。

原型分别保留完整扫描、只计算距离而不推入 TopK、只遍历存活行。去掉候选处理后耗时明显下降，但代码生成也随之变化，不能将两者相减视为精确的 TopK 成本。打分接口强制内联、把归约移进累加函数两个隔离试验未显示明确收益，未落入生产改动。只延迟排序键的位次比较，以及延迟构造整个候选位次的原型均有改善，后者进入真实 RPC 配对测量。

保留的生产改动仅涉及 TopK：

- 推入候选前，先用原 `flat::rank` 比较分数与现有阈值。严格更差时直接拒绝，不读取源内位次；可能入选或并列时才调用一次取位次闭包。
- 并列仍按完整的 `(source_rank, order, chunk, row)` 判定，包括 NaN 和 ±0。全序比较只在分数相等时比较位置，排序与筛选语义不变。
- 扫描的批量及标量路径、跨行块吸收均使用同一入口。闭包同步读取当前不可变快照，不保存或跨线程提交；不增加锁、数据结构、unsafe 或依赖。

距离核、累加和归约顺序、度量换算、TopK 的筛选批大小、四查询分组、行块、分波和候选内存上限均不变。没有按前几个维度提前停止距离计算，也没有跳过过滤校验。WAL、manifest、Parquet、恢复和发布协议不在本轮改动内。

### 第二轮正确性门

新单测断言严格更差的分数不执行取位次闭包；更好、并列、尚无阈值时执行一次，并按原全序接受或拒绝。覆盖零 take、有限值、NaN、±0、无穷值和不同来源。另一单测随机打乱来源与位次，用原来的完整比较作为独立排序模型，逐位核对多种 take；原有 3000 组 TopK 模型、距离逐位模型及串行/并行、快照、停服用例保留。

新增三条真实 3.x 差分按 L2/IP/COSINE 分别验证已提交与活跃数据源、覆盖、删除及再次发布；超过筛选批大小的输入包含重复向量，同时核对 nq1、nq4、nq5 和 offset。检索使用 0004 的 `hits` 比较口径，不要求参照实现在截断并列处返回完全相同的主键。

本轮重新构建的 native SHA256 为 `ee69a442db3a552538a44bb61b8bb6a6ef34bea2267a856f10864322b98ee9e6`，开发扩展与 wheel 字节一致。实际完成：workspace 全套（core lib 139）、core fault-injection 全套（lib 160）、默认 workspace 与 core FI 两套 Clippy `-D warnings`、fmt；benchmark/platform 41 passed。pymilvus 3.0.2 / 2.6.17 顺序执行，各 Python 232、差分 84 passed，无跳过或断言放宽。没有修改基准脚本，脚本指纹仍是第一轮的 `356381f3…`。

本轮未重跑 storage_interop（落盘、恢复与提交协议均未改），不把历史互通结果当作该产物的重测。Linux/Windows、真实断电、并发性能、其他度量/维度/位图密度/混合 WAL 布局不在本轮性能证据范围；对应正确性测试通过不等于已有性能结论。

## NaN 核对口径更正（2026-10-10）

上文“逐位核对四条结果”“逐位检查三度量与特殊值”在 NaN 上更正为：两边都是 NaN 即通过，非 NaN 仍逐位比较。原生 x86_64 首发验收中，该回归在 NaN 用例上因符号/payload 不同而失败；Rust 不保证 NaN 位模式，排序把所有 NaN 视为相同，对外顺序不受影响。口径与依据见 [flat.rs](../../crates/core/src/flat.rs) 模块说明及[首发准备验收](first-release-acceptance.md#原生运行发现并修复的测试缺陷)。本记录的测量数字与产物身份不变。
