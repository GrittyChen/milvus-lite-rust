# 批量检索性能专项

日期：2026-10-09。基线 `e23acd5`，参照 v3.2.1 / `43d1257`。性能目标及精度约束沿用 0001 / 0004；本轮不重新设计 0005 的计算池、任务提交、锁、候选内存上限、停服或公平性。

## 定位与最小改动

对独立服务连续发出百万行、128 维、nq100、FLAT L2 请求，macOS sample 的计算线程栈主要落在 `flat::diff_sq_lanes_batch` / `score_batch`，TopK.push 次之。采样期间请求明显变慢，采样耗时不进入正式表；等待栈不能直接解释为调度开销，未据此宣称调度是瓶颈。

单线程的隔离距离核探针，百万候选、4 查询、128 维，初步三次预热后值约 40–44 ms；展开内层循环约 36–37 ms。checksum 相同只作诊断，不替代逐位/差分验证，也不能将微测比例当作 RPC 收益。真实 RPC 冒烟差异较小，进一步配对计时后才能决定收益。

当前候选仅做两件事：

- 显式展开批量距离核的 4 条查询，把同一候选元素供四个独立累加器使用；每条查询每一路仍按相同 k 顺序累加。保留 16 路、同一归约树、尾部顺序、COSINE 换算和 NaN 处理。L2 仍逐元素相减再平方，没有 FMA、范数展开、unsafe 或额外依赖。
- 强制内联原 TopK.push，减少每个候选的调用开销；不改变 bound、筛选阈值、排序键、吸收或结果顺序。

组大小仍为 4，BLOCK_ELEMS、row_blocks、groups_per_wave 与 Compute::for_each 均未改；同时存活候选不因 nq 增长，读快照和磁盘协议不变。新回归用原嵌套循环对照新距离核，覆盖三度量、维度边界、32768 维、NaN、±inf、±0、有限大数与尾部，逐位核对四条结果。既有串行/并行、并列、稀疏存活行与生命周期用例继续作为门槛。
